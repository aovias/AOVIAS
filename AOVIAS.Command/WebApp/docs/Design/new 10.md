# PRAMAN UI Design System

Version 1.0
Healthcare Compliance Command Platform

This document defines the **visual language, UI components, layout patterns, and interaction principles** for PRAMAN.

All UI screens including **authentication, dashboards, compliance modules, audits, and reports** must follow this design system to maintain visual consistency.

---

# 1. Product Identity

PRAMAN is an **enterprise healthcare compliance platform** used by hospitals to manage:

• NABH accreditation
• compliance monitoring
• audits
• regulatory readiness

The interface must feel:

• trustworthy
• professional
• calm
• intelligent
• modern SaaS

Avoid designs that look like a **traditional hospital management system or government portal**.

Instead follow the visual quality of **Stripe, Linear, Notion, Vercel dashboards**.

---

# 2. Design Principles

### 1. Clarity over decoration

UI should prioritize clarity and usability over visual complexity.

### 2. Calm enterprise aesthetic

Use soft spacing, subtle shadows, and balanced typography.

### 3. Action-driven interface

Users should immediately understand what requires attention.

### 4. Workflow-first experience

Compliance management is a **journey**, not a list of forms.

### 5. Operational visibility

The system should always communicate **current compliance status**.

Global Structure

Top Navigation
Module Sidebar
Main Workspace
Activity Panel

Example layout:

Top Navigation (global navigation)

Sidebar (module navigation)

Main Workspace (primary UI)

Optional Activity Panel (alerts / activity feed)

---

Authentication pages use a **two-panel layout**.

Left Panel
Branding and product messaging

Right Panel
Login or onboarding interface

---

# 6. Spacing System

Use a consistent spacing rhythm.

Elements must never appear cramped.

Spacing hierarchy:

Small gap
Between label and input

Medium gap
Between form fields

Large gap
Between sections

Extra space
Between major UI modules

Spacing should feel **airy and balanced**.

# 7. UI Components

## Buttons

Primary Button

Used for main actions.

Examples:

Sign In
Create Hospital Account
Submit Compliance Report

Visual style:

Blue gradient
Rounded corners
Soft shadow

---

Secondary Button

Used for alternate actions.

Neutral background
Subtle border

Examples:

Cancel
Back

---

## Input Fields

Inputs should include:

Label above input
Optional helper text
Icon when relevant

Inputs must be visually aligned and evenly spaced.

Avoid heavy borders.

---

## Cards

Cards are the primary UI container.

Used for:

• KPI widgets
• compliance summaries
• feature modules

Cards should have:

• subtle shadow
• rounded edges
• balanced padding

Informational status

# 9. Dashboard Design

PRAMAN dashboards must prioritize **operational awareness**.

The main dashboard is called the **Command Center**.

Command Center includes:

Compliance Score
Hospitals requiring action
Upcoming audits
Compliance heatmap
Recent activity

Visual components:

KPI cards
charts
activity feed
alerts

---

# 10. Data Visualization

Avoid heavy data tables.

Prefer visual representations:

Compliance Score
Circular progress indicator

Department readiness
Heatmap

Audit schedule
Timeline

Trend analysis
Line charts

Tables should only appear for detailed lists.

---

# 11. Activity Stream

Replace traditional logs with **activity feed UI**.

Example:

Hospital uploaded infection control policy

NABH audit scheduled

Fire safety certificate expiring

Activity feed helps operators understand system state.

---

# 12. Micro Interactions

UI should feel responsive.

Examples:

Button hover glow
Fingerprint pulse animation
Status indicator blinking

Animations must be subtle.

Avoid flashy motion.

---

# 13. AI Layer

UI examples:

AI security monitoring indicator

AI insights panel

AI recommendations

Example message:

# 14. Trust Signals

# 15. Iconography

Icons should be minimal and modern.

Used for:

navigation
status indicators
feature cards
alerts

# 16. Responsive Behavior

The platform should remain usable on smaller screens.

Authentication panels should center vertically.

Forms should stack naturally.

Dashboards should adjust card layout responsively.

---

# 17. Tone of Voice

Text tone should be:

Professional
Clear
Encouraging

Example onboarding message:

Start Your Compliance Journey with Confidence

Avoid bureaucratic or technical sounding language.

PRAMAN should feel like:

A modern healthcare compliance command platform

A legacy hospital management system.

Every screen must reinforce:

Trust
Clarity
Operational insight
