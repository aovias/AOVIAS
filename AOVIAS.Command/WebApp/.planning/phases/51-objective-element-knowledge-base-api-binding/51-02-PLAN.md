# Phase 51 — Wave 2: Bind OE execution screen + wizard to Knowledge Base

## Goal

When **`ObjectiveElementExecutionScreen`** has resolved an OE (`tryApplyRouteObjectiveElement`), **load `NodeDetailsDto`** (or knowledge fallback) and expose signals/VM to **`OeExecutionWizardComponent`** so step content (**Understanding**, **Guidance**, **Evidence**, **Audit**) reflects **real** `KnowledgeItemDto` / requirement fields instead of placeholders — with graceful **loading / empty / 404** states.

## must_haves

- [ ] **Correlation strategy implemented in code:** (1) `getNodeDetails(oeId)` using route **`oeGuid`**; (2) on `404` / empty, retry by **`getKnowledgeByNodeCode(oe.code, frameworkId)`** where `frameworkId` comes from session/snapshot (`journey` framework id — confirm same GUID space as KB `frameworkId`).
- [ ] **Store or facade:** new signals e.g. `knowledgeBaseLoading`, `knowledgeBaseError`, `nodeDetails` / chosen `KnowledgeItemDto` — cleared on OE change and on destroy.
- [ ] **Field mapping (document in `knowledge-base-oe-wizard.mapper.ts` or equivalent):** pick one item from `knowledge[]` (document rule: e.g. first `isActive`, highest `version`). When KB data exists:
  - **Step 0:** `explanation` → Explanation card (replace `splitParagraphs(h.oeTitle)`); `whyItMatters` → Why it matters; optional kicker from `ComplianceNodeDto.code` / `title` — not full body from Journey title alone.
  - **Step 1:** `howToComply` → “How to comply”; optional teaser from `evidenceRequired` in “Evidence expectations”.
  - **Step 2:** `evidenceRequired` → “Evidence required” body (align with step 1 teaser).
  - **Step 3:** If showing KB audit prose, `auditChecklist` → checklist section; **score `range` (1–5)** must align with **`RequirementScoreDto.maxScore`** via an explicit product rule (transform, change `max` on input, or API contract) — **do not assume** 1–5 equals API scale.
  - **Step 4:** Summary echoes local eval state + optional KB titles.
- [ ] **Do not bind** `RequirementDetailDto.classification` to wizard eval tone radios unless product defines equivalence (different semantics).
- [ ] **Explicit non-KB:** Step 1 **Tasks** list and **Smart assist** remain stub / follow-up — no pretending KB supplies them.
- [ ] **Objective screen:** trigger load when `oeGuid` + workspace ready (same `effect` as today, extended — avoid duplicate HTTP).
- [ ] **Accessibility:** loading `aria-busy` on main wizard region when KB loading; error message non-dismissible or retry CTA.
