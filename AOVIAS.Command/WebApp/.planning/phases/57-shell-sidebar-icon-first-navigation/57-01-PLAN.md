# Plan 01 — Navigation config, icon registry, and deduplication rules

## Goal (wave)

Establish a **single config-driven** navigation model for the icon-first refactor: extend the **existing** `sidebar-nav.model.ts` types (preserve all **current routes** and **section order**), centralize **icon** definitions (20–24px target, token-compatible sizing in CSS), document **badge** keys per Action Center route, and define **deduplication** of **quick-actions** vs. main list so implementation waves do not fork two sources of truth.

## must_haves

- [ ] **No route path changes** — every `route` string in `getSidebarMenuSections()` remains valid and matches `app.routes` / lazy feature routes.
- [ ] **Hierarchy preserved** — all sections currently returned (`dashboard`, `compliance-execution`, `action-center`, `reports`, `audit-management`, `knowledge`, `administration`) remain; **Compliance Execution** and **Action Center** child items stay **Journey → Standards & Chapters → Evidence → Tasks** and **Findings → Issues & Risks → Alerts & Notifications** respectively.
- [ ] **Extended `SidebarMenuItem`** (or type alias `NavItem`) includes optional fields needed for icon-first UI: e.g. **`navBadgeKey`** (enum or string union: `findings` | `issues` | `alerts`) for badge wiring, **`ariaLabel`** if different from `label`, optional **`tooltip`** override — without breaking existing consumers (all new fields optional).
- [ ] **`sidebar-icons.registry.ts`** (or equivalent) holds **named** SVG snippets or icon components map keyed by stable id — **Journey** (route/map), **Standards** (book/layers), **Evidence**, **Tasks**, **Findings**, **Issues**, **Alerts** per stakeholder mapping; avoid duplicating huge strings across rows where the same icon repeats.
- [ ] **ADR / short doc** `docs/architecture/sidebar-navigation.md`: one-page **IA**, **badge semantics** (critical / warning / neutral), and explicit decision on **quick-actions strip**: remove duplicates **or** reduce to nonOverlapping shortcuts (choose one; default = **remove redundant** quick-actions that mirror Compliance/Action routes).
