# Plan 03 — Responsive shell: narrow viewports, bottom navigation (optional), touch UX

## Goal (wave)

Complete the **responsive** story: at **narrow viewports** (align with existing **767px** breakpoint already used by sidebar drawer), ensure **icon-first** nav remains **touch-friendly** (**min ~44px** hit targets), tooltips are **not** the-only hint on touch (use **aria-label**, **visible** labels in drawer, or **long-press** optional via Material no native long-press — prefer **drawer shows full labels** when open). Add **optional preferred** **bottom tab bar** for primary destinations (Compliance execution subset + Action Center subset + optional Dashboard) **reusing** the same route strings from **57-01** config (import `getSidebarMenuSections()` slice or export `getPrimaryBottomNavItems()` from model).

## must_haves

- [ ] **Overlay drawer:** Preserve **backdrop**, **Escape**, **focus trap**, **body scroll lock**, and **main pointer-events none** — z-index order unchanged or **documented** if bottom nav adds a layer.
- [ ] **Bottom nav (preferred):** Fixed bar **above** the 48px footer (or replace footer padding with `padding-bottom` on `main-content` so content is not obscured); **icons + short labels** or icons-only with **`aria-label`**; **active** state mirrors sidebar.
- [ ] **Config reuse:** Bottom nav items are **derived** from the same registry as sidebar — **no** second hardcoded route list (helper in `sidebar-nav.model.ts`).
- [ ] **Touch targets:** Nav rows and bottom nav tabs meet **≥44px** minimum height (token-based).
- [ ] **Header hamburger:** Existing mobile open/close **sidebar** flow remains; bottom nav is **complementary** (jump to route) not duplicate of hamburger **unless** product trims hamburger scope — default **keep both**: hamburger = full IA, bottom = fast lanes.
- [ ] **No backend / API** changes.
