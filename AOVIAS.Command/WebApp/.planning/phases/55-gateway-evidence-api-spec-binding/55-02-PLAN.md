# Phase 55 — Wave 2: JourneyDataService parity for §5.6–5.9 (detail, download, verify, version)

## Goal

Expose **typed** HTTP helpers on `JourneyDataService` for remaining Gateway evidence routes in `gateway-evidence-api-specification.md` **§5.6–5.9**, using the same `journeyBase` + `environment.apiBaseUrl` patterns as existing upload/delete/list. **UI binding is out of scope** unless a separate phase requests context-panel actions (download / verify / replace file).

## must_haves

- [ ] **§5.6** `getObjectiveElementEvidenceDetail(journeyId, oeId, evidenceId)` → GET JSON, map to a typed DTO (`EvidenceDetailDto`-shaped interface per spec wording: identity, title, types, `fileUrl`, `versions[]` — use optional fields where backend varies).
- [ ] **§5.7** `downloadObjectiveElementEvidenceFile(...)` → `HttpClient.get` with `responseType: 'blob'`, full URL under `apiBaseUrl`; **do not** route through `apiResponseInterceptor` envelope unwrap for blob (raw response). Document that callers must use `HttpClient` directly or a dedicated method that skips envelope mapping — verify how interceptors treat blob responses (adjust only if interceptor breaks blob).
- [ ] **§5.8** `verifyObjectiveElementEvidence(journeyId, oeId, evidenceId, body: VerifyOeEvidenceRequest)` → POST JSON (`accepted`, `remarks?`).
- [ ] **§5.9** Add **`buildEvidenceVersionFormData({ file, notes? })`** next to existing builders; **`uploadObjectiveElementEvidenceVersion(..., formData)`** POST multipart to `…/evidence/{evidenceId}/versions`.
- [ ] **Unit tests** in `journey-data.service.spec.ts`: assert URLs and HTTP method for each new method (HttpClientTestingModule), mirroring existing upload tests.
- [ ] If **`apiResponseInterceptor`** unwraps only JSON objects with `success`, document that blob GET must bypass or interceptor must no-op for `responseType === 'blob'` — implement minimal safe fix.
