# 34-02: Dashboard Component API Binding

## Objective
Bind `DashboardComponent` and its sub-components to live data from `getProgramOverviewSnapshot()`. Map API response fields to existing controls, add loading/error states, and maintain theme support.

## Field Mapping — API ↔ Dashboard Controls

### ✅ Confident Mappings

| API Field | Dashboard Control | How |
|---|---|---|
| `summary.completionRate` | Executive Summary → **"Readiness"** card | `value` = `Math.round(completionRate * 100) + '%'` |
| `tasksSummary.total` | Executive Summary → **"Total Tasks"** card | `value` = `total`, `label` = `'Across ' + frameworksActive + ' frameworks'` |
| `summary.overdueTasks` | Executive Summary → **"Critical Pending"** card | `value` = `overdueTasks`, `color` = `overdueTasks > 0 ? 'danger' : 'success'` |
| `summary.upcomingExpiries` | Executive Summary → **"Upcoming Expiries"** card | `value` = `upcomingExpiries`, rename from "Upcoming Audits" |
| `summary.avgComplianceScore` | Gauge Chart → **"Compliance Score"** | `value` = `Math.round(avgComplianceScore)` |
| `summary.completionRate` | Gauge Chart → **"Completion Rate"** | `value` = `Math.round(completionRate * 100)` (rename from "Audit Confidence Score") |
| `tasksSummary.byPriority` | **Risk Distribution** (pie chart) | Map `{High, Medium, Low}` → `RiskData[]` with `danger/warning/blue` colors |
| `frameworks[]` | **High Risk Chapters** → rename "Framework Overview" | Map `frameworkCode → chapter`, `avgScore → score`, derive riskLevel from score |
| `frameworks[]` | **Chapter Breakdown** (bar chart) → rename "Framework Score Breakdown" | Map `frameworkCode → chapter`, `avgScore → score` |
| `alerts[].severity === 'High' && !acknowledged` | **Alert Banner** | Show first unacknowledged high-severity alert |
| `generatedAt` | **"Last updated"** timestamp | Format with `DatePipe` as relative time |
| `organizationName` | **Dashboard subtitle** | Replace hardcoded "Apollo Hospitals, Chennai - NABH Accreditation" |

<task id="01" name="Add loading/error states to DashboardComponent">
### Inject service, fetch on init, add loading/error state signals

**File:** `src/app/features/dashboard/pages/dashboard.component.ts`

- Import `DashboardService`, `DashboardSnapshot`
- Inject `DashboardService` via `inject()`
- Add signals: `snapshot`, `isLoading`, `error`
- On component init (`OnInit` or constructor with `effect`), call `getProgramOverviewSnapshot()`
- Set `isLoading = true` before request, `false` on complete
- Set `snapshot` on success, `error` on failure
- Add loading skeleton and error state in template

```typescript
private dashboardService = inject(DashboardService);

snapshot = signal<DashboardSnapshot | null>(null);
isLoading = signal(true);
error = signal<string | null>(null);

constructor() {
  this.loadSnapshot();
}

loadSnapshot(): void {
  this.isLoading.set(true);
  this.error.set(null);
  this.dashboardService.getProgramOverviewSnapshot().subscribe({
    next: (data) => {
      this.snapshot.set(data);
      this.isLoading.set(false);
    },
    error: (err) => {
      this.error.set('Failed to load dashboard data');
      this.isLoading.set(false);
    },
  });
}
```

Template additions:
```html
@if (isLoading()) {
  <div class="dashboard-skeleton">…</div>
}
@if (error()) {
  <div class="dashboard-error">
    <p>{{ error() }}</p>
    <button (click)="loadSnapshot()">Retry</button>
  </div>
}
@if (snapshot()) {
  <!-- existing dashboard content bound to snapshot() -->
}
```

### Verification
- [ ] Loading state shown while API call is in flight.
- [ ] Error state with retry button on failure.
- [ ] Snapshot data populates all child components.
- [ ] `refreshDashboard()` re-fetches from API.
</task>

hasCriticalIssues = computed(() => {
