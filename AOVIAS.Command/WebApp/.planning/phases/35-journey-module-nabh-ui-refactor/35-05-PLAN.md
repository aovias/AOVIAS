# 35-05: Performance, Trends, Dashboard Alignment & Summary Report

## Objective
Add **virtual scrolling** or equivalent for large OE lists, **lazy load** standards on chapter change, **trend/analytics** widgets (OE/standard/chapter/risk evolution — chart or mini-sparklines using existing patterns), align **journey overview metrics** with **NABH compliance score** (replace generic “completion %” where required), and produce **35-SUMMARY.md** documenting removed/added components and integration points.

## Tasks

<task id="01" name="CDK Virtual scroll">
### Virtualize OE lists
- `cdk-virtual-scroll-viewport` in `JourneyMainWorkspace` or `OeCard` list container.
- **Item size** fixed or `autosize` (if available); test with 500+ mock OEs.
- **OnPush** compatibility: `Observable`/`signal` updates trigger detach only.

**must_haves:**
- No scroll jank on chapter switch (destroy viewport on chapter id change).
</task>

<task id="02" name="Lazy standards">
### `*ngIf` / `defer` first paint
- Load **only** standards for selected chapter when snapshot is large (split mock or API pagination placeholder).
- Service method `getStandardsForChapter(chapterId)` optional if backend supports.

**must_haves:**
- No duplicate HTTP calls (shareReplay in service).
</task>

<task id="03" name="Trends & analytics">
### Mini charts
- Reuse dashboard chart patterns (SVG or existing chart lib if project has one).
- Widgets: score trend per OE (selected), chapter improvement, risk evolution — **mock series** first.

**must_haves:**
- Responsive; theme-aware colors.
</task>

<task id="04" name="Journey overview metrics">
### Replace “completion %” with **compliance score** (NABH)
- `JourneyOverviewCards` or top bar: **Core compliance %**, **failed core count**, **OEs ≤ 3 count**, **open action plans**.
- Wire to store computed from snapshot.

**must_haves:**
- Copy matches NABH terminology from spec.
</task>

<task id="05" name="Edge cases & validation UX">
### Centralize validators
- `naRequiresJustification`, `coreOeBelowThreshold` (highlight), empty states, partial API responses.

**must_haves:**
- User-visible messages for blocked actions.
</task>

<task id="06" name="Summary report">
### Write `35-SUMMARY.md` in phase folder
- **Removed**: clause components, interfaces, CSS blocks (list files).
- **Added**: component tree, services, store, key files.
- **API mapping**: table of endpoints → models.
- **Follow-up**: backend gaps, tests recommended.

**must_haves:**
- Complete file list for PR description.
</task>
