# 35-03: Standard Sections & Objective Element (OE) Cards

## Objective
Build the **main content area**: **expandable Standard** blocks, each containing **OE cards** (the core unit). Implement **NABH scoring** display (1–5 + Poor→Full labels), **classification badges**, evidence status, audit status, action-required banner (score ≤ 3), ownership, timeline, and primary actions (view tasks, upload evidence, details).

## Tasks

<task id="01" name="StandardSectionComponent">
### Expandable/collapsible standard
- Header: standard code, description (truncated + expand), completion %, **risk badge**, core summary line.
- Use `MatExpansionModule` or custom accordion with `aria-expanded`.
- Lazy: **do not** render OE list body until expanded (first open) to reduce initial DOM.

**must_haves:**
- `trackBy` on standard id.
- Styling: clear separation (border, spacing) per spec.
</task>

<task id="02" name="OeCardComponent">
### OE card — identity + scoring + status + actions
- **Identity**: OE code, description (line-clamp).
- **Classification badge**: Core (emphasized), Commitment, Achievement, Excellence — color map per `ui-brand` / existing tokens.
- **Scoring**: numeric 1–5 + label; **color** bar or dot (red/yellow/green).
- **Evidence**: Complete | Missing | Pending verification.
- **Audit**: Compliant / Non-compliant / NA.
- **Action**: if score ≤ 3 → prominent “Action plan required”.
- **Ownership**: department + user (use `RoleRegistryService` or display names if ids only).
- **Timeline**: last updated, due / next review.
- **Actions**: buttons → emit events (`viewTasks`, `uploadEvidence`, `openDetails`).

**must_haves:**
- No clause naming.
- **Accessibility**: button labels, contrast for badges.
- **OnPush** + `input()` signals per Angular 19+ style used in project.
</task>

<task id="03" name="JourneyMainWorkspaceComponent">
### Compose standards for selected chapter
- Input: `chapter` from store.
- Apply **lifecycle filters** (e.g. Final: hide non-core OEs if store says so — implement filter pure functions in `journey-filters.ts`).
- **Empty states** for no standards / no OEs.

**must_haves:**
- Selecting OE sets `selectedOeId` in store (for drawer in 35-04).
- **No** full list re-fetch on expand; use cached snapshot.
</task>

<task id="04" name="Filter utilities">
### Pure functions: `filterOeByLifecycle`, `sortOesByCode`
- Unit-testable; imported by workspace + store.

**must_haves:**
- Deterministic ordering (OE code / numeric suffix if applicable).
</task>

## Verification criteria
- [ ] Expand standard → OEs appear; collapse → children not destroyed if using `*ngIf` lazy (acceptable) or cache in component state.
- [ ] Score ≤ 3 shows action plan requirement UI.
- [ ] Core classification visually distinct.

## must_haves
- **OE** is the **leaf** unit; standards group OEs only.
- **Clause** UI **absent**.
