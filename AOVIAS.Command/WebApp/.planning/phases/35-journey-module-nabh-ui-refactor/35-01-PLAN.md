# 35-01: Domain Models, Data Layer & Feature Scaffolding

## Objective
Establish **typed domain models** for `Chapter → Standard → ObjectiveElement` (OE), NABH enums (score 1–5, classification, audit lifecycle, evidence status), and **remove `Clause` terminology** from the feature. Introduce a **data service** + **workspace store** (signals) so UI work in later waves binds to real structure—not mock clause arrays.

## Tasks

<task id="01" name="Create journey model layer">
### Add `features/journey/models/` with tree-aligned interfaces
**New files (conceptual):**
- `nabh.enums.ts` — `NabhScore` (1|2|3|4|5), `ScoreLabel`, `OeClassification` (`core` | `commitment` | `achievement` | `excellence`), `EvidenceStatus`, `AuditLifecycleMode`, `AuditComplianceStatus`, `ActionPlanStatus`.
- `objective-element.model.ts` — `ObjectiveElement`: id, code, description, classification, score, scoreLabel, evidenceStatus, isNa, naJustification?, auditStatus, departmentId?, assigneeUserId?, lastUpdatedAt?, dueAt?, nextReviewAt?, actionPlans[] (typed), riskLevel?, flags? (e.g. `requiresActionPlan` derived from score ≤ 3).
- `standard.model.ts` — `ComplianceStandard`: id, code (e.g. AAC.1), description, completionPercent, riskBadge, coreSummary?, objectiveElements[].
- `chapter.model.ts` — `JourneyChapter`: id, code, name, completionPercent, risk, coreComplianceStatus, openIssuesCount, pendingAuditFlag?, standards[].
- `journey-tree.model.ts` — root: `JourneyFrameworkNode` or flat `JourneyWorkspaceSnapshot` with chapters[], metrics for accreditation panel.

**must_haves:**
- No interface named `Clause` or `clause*` in `features/journey/models/`.
- OE supports `IsNA` + optional justification field for validation rules in later plan.
</task>

**must_haves:**

</task>

<task id="03" name="JourneyWorkspaceStore">
### Signals-based store: selection + lifecycle + filters
- State: `selectedChapterId`, `selectedStandardId`, `selectedOeId`, `lifecycleMode`, `chapterSearch`, `sortByRisk` (boolean), `readOnly` (derived from lifecycle + role placeholder).
- **Immutability**: update via `update()` / spread; no shared mutable arrays.
- Selectors: `filteredChapters()`, `selectedChapter()`, `standardsForChapter()`.

**must_haves:**
- Sorting chapter list does **not** mutate source snapshot from API.
- Lifecycle mode enum drives a signal consumed by later waves.
</task>
