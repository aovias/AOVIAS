# 35-07: Journey API — Store, Component Wiring, UX & Integration Summary

## Objective
Wire **JourneyWorkspaceStore** and journey **components** to **`JourneyDataService` HTTP** APIs: optimistic updates + rollback, **loading/error** UX (skeletons, section spinners, disabled actions), **toast/snackbar** for failures and validation messages, **lifecycle/read-only** from API when available, and **debouncing** where rapid edits occur. **Do not** change component templates’ structure or layout hierarchy — only bindings, handlers, and state. Produce **`35-UI-BINDING-SUMMARY.md`**.

## Tasks

<task id="01" name="JourneyWorkspaceStore">
### Load & cache
- `initFromRoute()`: obtain `journeyId` via resolver from 35-06; on success set `_snapshot`; on error set `loadError` with **retry** callback stored or method `retryLoad()`.
- After successful PATCH for OE: merge server response into snapshot if API returns updated OE; else keep optimistic patch.
- **Optimistic updates:** extend `patchObjectiveElement` flow: call `patchObjectiveElement` on service, `patchObjectiveElement` in store optimistically, **on error** revert prior OE state and show snackbar.
- **OE-level loading:** add signals e.g. `oeMutationInFlight = signal<Set<string>>(...)` or per-oe `updatingOeId` to disable Save / toggles during request.

### Lifecycle from API
- If workspace DTO includes `lifecycleMode` / `readOnly`: initialize `lifecycleMode` and derived `readOnly` from API instead of default `self_assessment` only.
- Preserve existing **filter rules** (`filterOesByLifecycle`) — server remains authoritative for mutations.

**must_haves:**
- Sorting/filtering still does not mutate cached snapshot arrays in place (copy-on-write).
</task>

<task id="02" name="Oe detail drawer — PATCH NA / score / remarks">
### `oe-detail-drawer.component.ts`
- `saveNa`: after validation, call `JourneyDataService.patchObjectiveElement` with `{ isNa, naJustification }` (and other fields if backend expects combined payload).
- Map **400** validation errors (NA without justification) to `naError()` or snackbar from `error.error` / `errors[]`.
- If score/audit remarks become editable: same pattern — debounce 300ms optional for text fields.

**must_haves:**
- Read-only mode: no HTTP mutation; UI already disables controls.
</task>

<task id="03" name="Evidence tab & upload">
### `journey.component.ts` + `journey-evidence-tab`
- Replace `noop()` / `onUploadEvidence` stub: open file picker or dialog → `POST .../evidence` → on success refresh evidence for OE (re-fetch OE slice or merge response).
- List evidence from **GET** when drawer opens or tab activates if not embedded in workspace payload.

**must_haves:**
- Theme-aware loading states; no layout change to tab buttons/grid.
</task>

<task id="04" name="History timeline">
### `oe-history-timeline` + store
- If history not fully in workspace: `GET .../history` when drawer opens for selected OE (with loading flag on timeline section).
- Merge into `detail` or store without duplicating events.

**must_haves:**
- Empty history: show existing empty state pattern.
</task>

<task id="05" name="Error & loading UX">
### Patterns (match Phase 34 / dashboard)
- Initial page load: replace plain "Loading journey…" with **skeleton** blocks (header + metrics + grid placeholders) if project already has skeleton pattern; else minimal **spinner** consistent with dashboard.
- Use **`NotificationService`** or **MatSnackBar** (project standard) for: network failure, timeout, partial save, validation messages from API.
- **Retry:** banner or snackbar action for workspace load failure calling `store.retryLoad()` / `initFromRoute()`.

**must_haves:**
- Light/dark: use existing CSS variables (`--card-bg`, `--text-primary`, etc.) — no new hardcoded colors.
</task>

<task id="06" name="Validation & warnings">
- Surface backend messages: NA without justification, score rule violations, evidence required warnings — map API error payload to user-visible strings.
- Client-side `naRequiresJustification` remains; align with server rules.

**must_haves:**
- No silent failures on PATCH.
</task>

<task id="07" name="Performance">
- **Avoid redundant workspace refetch** on navigation if snapshot cached and journeyId unchanged.
- **Debounce** rapid PATCH for text fields if applicable.
- Invalidate cache on `AppContextService` hospital/framework switch (already partially in place).

**must_haves:**
- Document cache strategy in summary doc.
</task>
