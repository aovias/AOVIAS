# Phase 49 — Plan 02: JourneyWorkspaceStore orchestration, caching, OperationalMode from API

## Phase goal (backward)

After this wave, **`JourneyWorkspaceStore`** loads real data via **`JourneyDataService`** (forkJoin or equivalent): session + dashboard + chapters; on chapter select loads **standards** for that chapter; on OE select optionally refreshes **OE detail** for full evidence/history. **`lifecycleMode`** initializes from **`session.operationalMode`** and **`setLifecycleMode`** / mode advance calls **`PATCH operational-mode`** then reloads session + dashboard + chapters. **`readOnly`**, **`snapshotReadOnly`**, **`modeProgression`** drive locks (replacing pure client `isModeLocked` where API provides). **`selectedOeChangedSinceLastAudit`** uses **`ObjectiveElementDto.changedSinceLastAudit`** when present. Local-only wizard step state remains; **no** `POST …/wizard/progress` call.

## must_haves

- [ ] Replace `loadMockData` primary path with async pipeline; **`JourneyMockWorkspaceService`** retained only behind explicit dev flag or removed if unused (see task).
- [ ] **`journeyId`** resolution: if null, **do not** silently use `mock-nabh-hospital-6` in production build — surface `loadError` + CTA (align with existing empty states).
- [ ] **Partial updates:** PATCH OE merges response; optional **`overview`** updates dashboard slice.
- [ ] **409:** on PATCH OE, refetch OE GET and surface user message.
- [ ] **Mode change:** after PATCH, invalidate standards cache for all chapters or at least selected.
- [ ] `ng build` passes.
