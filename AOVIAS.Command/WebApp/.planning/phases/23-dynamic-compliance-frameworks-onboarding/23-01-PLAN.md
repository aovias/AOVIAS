# Plan 23-01: Onboarding → Framework selection from API (`GET /frameworks/all-frameworks`)

## Objective

Replace the static compliance framework grid in the AI onboarding wizard with a **dynamic, API-driven** list. On init, fetch frameworks, bind `name` → `<h3>`, `authority` → `<p>`, use **`platformId`** as the sole selection key (multi-select preserved). Persist selected platform IDs in onboarding state and include them in the **onboarding submission payload** where the app builds `OnboardingRequest`. Provide **loading and error** UX consistent with the departments lookup step (retry, non-blocking messaging).

## Scope Notes

- **In scope:** `FrameworkSelectorStepComponent`, `OnboardingDataService` (remove static `getFrameworks()`), shared lookup loading pattern, `AiSetupAssistantComponent` completion summary (remove slug → label map), models/store/payload fields for platform IDs.
- **Out of scope unless required for compile:** Header framework dropdown, reporting filters, `ComplianceContextService` — unless they import removed APIs.
- **Endpoint path:** `GET /frameworks/all-frameworks` relative to `environment.apiBaseUrl` (full path `/api/v1/frameworks/all-frameworks` with current env).
