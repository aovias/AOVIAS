# Phase 39 — Wave 2: Journey Execution workspace (3-column polish)

## Goal (backward from success)

The **Execution** experience (chapter rail + standards/OE center + action context) feels **compact, layered, and calm**: hairline borders or soft elevation per Wave 1 tokens, **higher information density** in chapter cards, **single-line** standard headers (title + score + badge) where layout allows, **shorter** OE table rows with clearer columns and less grid noise, and **clear** primary vs secondary actions — **without** new inputs, routes, store fields, or APIs.

## must_haves

- [ ] All styling uses tokens from Wave 1 + existing `var(--color-*)` / `--space-*` / `--shadow-*`; **no** new hex/rgba in `src/app/features/journey/**/*.scss` (Phase 38 discipline preserved).
- [ ] Chapter cards: reduced min-heights/padding; progress bar + title + meta **tight** vertical rhythm; search/sort row spacing consistent with `--section-gap` rules from DESIGN_RULES.
- [ ] **StandardCardComponent:** header row **horizontal** alignment (title, score, classification badge); body uses compact card padding where appropriate; **collapsible** behavior uses **only** existing `expanded` + `standardToggle` — wire parent if state exists but UI does not reflect accordion; **do not** add new expand buttons.
- [ ] OE table: reduced row height; column padding/alignment; lighter row/divider borders (`--border-width-hairline` + subtle color).
- [ ] Right stack (action panel, accreditation, progress): consistent card shell matching DESIGN_RULES density; primary CTA visually dominant; secondary/tertiary lighter.
- [ ] Subtle **icons** on existing actions/status (reuse project icon components); **badge** shapes unified (radius/padding/font) per DESIGN_RULES.

## Non-goals

- No changes to `JourneyWorkspaceStore` contracts, HTTP, or VM shapes except **class/CSS** binding adjustments if required for layout (avoid).
- No new OE columns or filters.
