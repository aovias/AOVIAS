# Phase 54.2 — Wave 2: API calls + minimal success/error + refresh

## Goal

When **`enableOeWizardEvidenceUpload`** is **true**, **`triggerUpload()`** (or explicit “Upload” control if already added — prefer **reusing** `triggerUpload` bound to a primary button or post-selection) **validates** via `validateEvidenceFilesForMode`, builds FormData via **`buildSingleEvidenceFormData` / `buildBulkEvidenceFormData`** (reuse `buildSinglePayload` / `buildBulkPayload` internals or call builders directly with `OE_EVIDENCE_DEFAULT_EVIDENCE_TYPE`), then calls **`JourneyDataService.uploadSingleEvidence(jid, oeId, fd)`** or **`uploadBulkEvidence`** — **no** manual URL concatenation in the component. On success: **snackbar** “Evidence uploaded successfully” (single) or message derived from bulk response; on error: **generic** “Upload failed. Please try again.” Clear `evidenceUploadFiles` after success. **Optional** `LoggerService` / debug logs with `journeyId` + `oeId` only if existing patterns allow.

## must_haves

- [ ] `inject(JourneyDataService)` in wizard only when needed (or always inject but unused when flag false — prefer **conditional** subscription paths only when flag true to avoid tree-shaking noise — either is acceptable).

- [ ] `takeUntilDestroyed` or `DestroyRef` on subscriptions (match `JourneyWorkspaceStore`).

- [ ] Before POST: `if (!environment.enableOeWizardEvidenceUpload) return;` at start of upload path, or guard entire method.

- [ ] Resolve `journeyId` and `objectiveElementId` from `JourneyWorkspaceStore`; if either missing, show error toast and **do not** POST.

- [ ] Single response: read `evidenceId` from `RegisterOeEvidenceResponseDto` (optional); success message **exact** “Evidence uploaded successfully” per brief (or reuse `NotificationService` if project standard).

- [ ] Bulk response: extend DTO **only** after backend contract confirmed — add `BulkEvidenceUploadResponseDto` with optional `successCount`, `failureCount`, `items`; map to “X files uploaded successfully” / “Y files failed” when fields present; else fallback message **“Bulk upload completed”** or generic success.

- [ ] Error: `catchError` / `subscribe` error callback → generic failure string (reuse `formatHttpError` from store only if copied as private one-liner **or** inject `NotificationService`).

- [ ] After success: `evidenceUploadFiles.set([])`; `evidenceUploadValidationError.set(null)`; call **public** store refresh method (new wrapper around `refreshObjectiveElementDetail`).

- [ ] **No** progress UI, **no** retry buttons, **no** refactor of `uploadEvidenceFile` on store beyond the thin public refresh helper.

- [ ] **No** `postEvidenceMultipart` duplication — wizard uses `uploadSingleEvidence`/`uploadBulkEvidence` + pre-built FormData.
