# 37.1-02: Left and center workspace components (navigation + standards + OE table)

## Objective
Implement the execution workspace navigation and standards work area with reusable OnPush components, tokenized styling, and event-driven interaction boundaries.

## Tasks

<task id="01" name="Build left chapter navigation panel">
- Create `chapter-navigation` with:
  - title, search input, sort toggle (Risk/Code)
  - chapter list rendering via `chapter-item`
- Create `chapter-item` row card with:
  - chapter code/title
  - risk indicator
  - count badge
  - progress bar
  - active/hover states
- Emit chapter selection events upward only.

**must_haves:**
- Search and sort controls are keyboard navigable.
- Risk visual cues use semantic tokens only.
</task>

<task id="02" name="Build standards center panel and expandable cards">
- Create `standards-panel` with:
  - section title/subtitle
  - compliance summary + status badge
  - open issues indicator
- Create `standard-card` expandable component with:
  - code + title
  - circular compliance score
  - classification badge
  - expand/collapse toggle
- Maintain expanded state in container/store, not within rendering-only children.

**must_haves:**
- Expand/collapse works via output events.
- No business logic in card/panel components.
</task>

<task id="03" name="Build OE table and row components">
- Create `oe-table` and `oe-row` with required columns:
  - OE Code, Title, Classification, Score, Status, Evidence Count, Actions
- Implement status presentation variants:
  - compliant
  - partially compliant
  - non-compliant
- Action column exposes `View` interaction as output event.

**must_haves:**
- Table has ARIA label and semantic structure.
- Row status and action styles are tokenized.
</task>

## Verification criteria
- [ ] Left panel supports search/sort and chapter selection outputs.
- [ ] Center panel supports standard expand/collapse and renders OE tables.
- [ ] OE row interactions bubble to container for right-panel updates.
- [ ] All new components use OnPush + explicit Input/Output APIs.

## must_haves (goal-backward)
- Users can navigate chapter -> standard -> OE quickly with low friction.
- Center panel clearly exposes execution workload and issue density.
