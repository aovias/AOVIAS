# 37.1-03: Right action panel, accessibility, token migration, and final verification

## Objective
Complete the mission-control experience by implementing the right contextual action column, enforcing accessibility and interaction quality, and verifying strict token compliance for the entire execution screen.

## Tasks

<task id="01" name="Build right context/action panel">
- Create `action-panel` with sections:
  1) Selected OE details
  2) Primary actions
  3) Quick actions
- Create `progress-card` section for journey progress:
  - current score
  - progress bar
  - compliance badge
  - evidence summary
  - last updated timestamp
- Wire outputs for:
  - Start/Resume Journey
  - View History
  - Upload Evidence
  - Add Task
  - View Timeline

**must_haves:**
- Right panel updates when OE row selection changes.
- Action handlers remain in container/store; panel stays presentational.
</task>

<task id="02" name="Finalize interaction and accessibility behavior">
- Ensure keyboard support for:
  - chapter list
  - standard expand/collapse controls
  - OE row view action
  - right-panel action buttons
- Add ARIA labels/roles for:
  - chapter list
  - standards cards
  - OE table and rows
  - action groups and quick actions
- Validate focus-visible states and contrast in both light/dark themes.

**must_haves:**
- All interactive controls have visible focus state.
- No interaction depends on pointer-only behavior.
</task>

<task id="03" name="Token governance and quality gates">
- Migrate any hardcoded colors in touched execution screen files to semantic tokens.
- Add semantic token aliases only in centralized token files when missing.
- Verify:
  - no inline styles
  - no raw hex values in touched feature styles
  - no raw px literals in touched feature styles (except token definitions)
- Run build/lint checks and update verification notes.

**must_haves:**
- `ng build` passes.
- Lint for touched files is clean or only pre-existing unrelated issues remain.
</task>

## Verification criteria
- [ ] Right panel reflects selected OE context and supports all specified actions.
- [ ] Mission-control interactions are keyboard-accessible and ARIA-labeled.
- [ ] Execution screen styling remains token-driven and theme-safe.
- [ ] Build passes; verification notes are recorded.

## must_haves (goal-backward)
- Execution screen is operationally actionable, not just informational.
- UI architecture remains reusable and maintainable for future data binding.
