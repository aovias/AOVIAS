# 36-02: Objective Element column logic and scoring engine (foundation)

## Objective
Implement **NABH 6th Edition–aligned** derivation for OE columns (mandatory, scorable, applicable, documentation required, tags, department, role, frequency, evidence category, **weight** from classification) and **pure scoring + accreditation decision** helpers aligned with **PDF** rules (final / surveillance / re-accreditation), including **overall ≥80%** logic with **correct OE band denominators** (Core+Commitment vs +Achievement vs +Excellence). **No API** — ready for backend swap.

## Tasks

<task id="01" name="Classification and weight mapping">
### Enums and mapping
- Introduce **`Classification`** numeric enum per spec: `Core = 1`, `Commitment = 2`, `Achievement = 3`, `Excellence = 4` (or align names to existing `OeClassification` with a **bidirectional map**).
- **`getClassificationWeight(classification)`**: Core → 0, Commitment → 1, Achievement → 2, Excellence → 3.
- **`isMandatory(classification)`**: Core only.
- **`isScorable`**: default `true` unless spec adds exceptions (document in util).
- **`isApplicable`**: default `true` unless OE flagged conditional (add optional `conditional?: boolean` on mock OE if needed).

**must_haves:**
- Single source of truth for weight → used by analytics tab.
</task>

<task id="02" name="oe-derivation.util.ts">
### Derived fields from OE text + classification
- **`isDocumentationRequired(oe)`**: true if description/title matches keywords: `policy`, `record`, `document`, `procedure`, `log`, `register`, `report` (case-insensitive).
- **`extractTags(text)`**: auto-tags from `patient safety`, `infection control`, `audit`, `training`, `documentation` (extend list as needed).
- **`inferDepartment(text)`**: rules — e.g. `infection` → Infection Control, `medication` → Pharmacy, … + default.
- **`inferResponsibleRole(text)`**: `infection` → Infection Control Nurse, `clinical` → Doctor/Nurse, `admin` → Administrator, default Quality Manager.
- **`inferFrequency(text)`**: `monthly` → Monthly, `each patient` → Per Patient, default As Applicable.
- **`inferEvidenceCategory(text)`**: policy → Document, logs → Record, audit → Audit, training → Training Evidence (keyword-based).
- Export a **`deriveOeColumns(oe: ObjectiveElement)`** object for UI binding (or individual getters used by templates).

**must_haves:**
- Pure functions; testable; no Angular DI.
- Document keyword lists at top of file for CTO review.
</task>

<task id="03" name="journey-scoring.util.ts">
### Scoring helpers (aggregates)
- **`getStandardScore(standard)`** — average OE score (exclude NA); **≥ 4** check per standard vs PDF.
- **`getChapterScore(chapter)`** — average across OEs or standards per product convention; **≥ 4** vs PDF.
- **`getCumulativeCompliancePercent(oes, bandFilter)`** — numerator/denominator style matching PDF: sum of scores / (5 × count) for applicable OEs in **scope** (exclude NA). Support filters: **Core+Commitment only** (562), **+Achievement** (622), **all 639**.
- **`getCoreCompliance`** — % of Core OEs with score ≥ 4 (and list failures).

**must_haves:**
- Pure functions; document **which OEs are in scope** per `NabhAssessmentPhase` (see task 04).
- No HTTP.
</task>

<task id="04" name="nabh-accreditation-decision.util.ts">
### Accreditation decision engine (PDF pp. 603–678, summary table pp. 686–700)
- Add **`NabhAssessmentPhase`**: `'final' | 'surveillance' | 're_accreditation'` (map from `AuditLifecycleMode` in a small adapter — `self_assessment` / `internal_audit` may use **`final`** rules for practice or a separate **`practice`** mode).
- Implement **`evaluateAccreditationEligibility(snapshot, phase, thresholds)`** returning:
  - Pass/fail on: **overall cumulative ≥ 80%** for the **scoped OEs** per phase;
  - **Core:** every Core OE **≥ 4**;
  - **Commitment / Achievement / Excellence** sub-80% checks as per **summary table** row for that phase;
  - **Standard:** max count of OEs **≤ 2** per standard (**1** at final/surveillance per PDF; **0** at re-accreditation per PDF table);
  - **Chapter & standard averages ≥ 4**;
  - **OEs ≤ 3** must have **accepted** action plan (extend `OeActionPlan` or eligibility with `hasAcceptedActionPlan` if missing).
- Populate **`violations: string[]`** for `AccreditationEligibility` for panel display.
- Keep **`NABH_THRESHOLDS`** as defaults but **reference PDF** in comments (80%, min 4).

**must_haves:**
- Behavior matches **PDF table** on p. 686–700 for the three columns (Final / Surveillance / Re-accreditation) — unit tests strongly recommended for golden cases.
- `AccreditationDecisionPanelComponent` binds to new evaluator output (or computed signal from store).
</task>

<task id="05" name="Store integration (optional signals)">
### Expose derived metrics
- Optional computed on store: **`accreditationEvaluation`** = `evaluateAccreditationEligibility(snapshot, mappedPhase, NABH_THRESHOLDS)` when snapshot or lifecycle changes.
- Components consume utils for tab analytics; **single** eligibility pipeline for header panel.

**must_haves:**
- No duplicate scoring logic in templates.
</task>
