# Phase 47 — Plan 01: Execution workspace layout system (grid, breakpoints, scroll)

## Phase goal (backward)

After this wave, **`ExecutionScreenComponent`** uses a **responsive layout system** with **defined breakpoints**, **no overlapping panels**, **clear column/stack behavior**, and **predictable scroll regions** (desktop: per-panel where appropriate; mobile: **primary vertical flow** without arbitrary `40vh` traps that hide standards).

## must_haves

- [ ] **Desktop:** three regions — **left** chapter nav, **center** standards/OE, **right** context — with **min-height 0** and **overflow** rules that prevent parent/child scroll clash.
- [ ] **Tablet:** documented breakpoint where **center** remains primary; **right** column **not** inline full-width (placeholder structure or **hidden** off-canvas slot — full behavior in **47-03**).
- [ ] **Mobile:** **stack order**: header → chapters → standards → context; **standards** region **full width**, **min-height** allows **readable** OE list; remove or replace **fixed 40vh** panel caps that make standards unusable.
- [ ] **CSS** uses **tokens only** (`--space-*`, `--section-gap-*`, `--radius-*`, etc.) per `DESIGN_RULES.md`.
- [ ] `ng build` passes.
