# Phase 56 — Plan 03: UX, observability, retries & verification

## Phase goal (backward)

After this wave, users see **clear loading** for long reads, **recoverable** messages on real failure (network, **true** timeout, 5xx), and **no scary generic** copy for **benign cancel** when superseded by a newer load. **Automatic retries** are **not** added globally; if a **narrow** retry is introduced for **idempotent GET** only, it must use **exponential backoff**, **cap** attempts, and **never** retry **4xx** except **408** if product demands (default: **no** retry on 408). **Dev** logging distinguishes **abort**, **timeout**, and **server error**.

## must_haves

- [ ] `formatHttpError` (or successor) maps **status 0** to user-facing **network / interrupted** copy; **timeout** (`TimeoutError` from RxJS) to **deadline exceeded** + retry; **does not** claim “server bug” for client-side abort.
- [ ] **Superseded** load cancellation: either **silent** (no toast) or debug-only log — **no** error toast when `loadGeneration` / `chapterGen` shows stale.
- [ ] `LoggerService`: **debug** in dev for aborted requests (URL + correlation id if present); **no** PII.
- [ ] Unit tests: **latest-wins** chapter standards (two overlapping ids → final merge matches last selection); workspace `switchMap` cancels prior mock observable (use `HttpTestingController` or cold observables).
- [ ] `56-VERIFICATION.md` lists acceptance criteria checklist with signoff notes.
- [ ] `ng test` for new specs + `ng build` passes.
