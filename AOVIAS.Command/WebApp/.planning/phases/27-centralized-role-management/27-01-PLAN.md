# Plan 27-01: Canonical role IDs, centralized labels, onboarding team dropdown

## Objective

Introduce a **single source of truth** for application roles: **canonical string IDs** (`ORG_ADMIN`, …) for **APIs and storage**, and **user-friendly labels** only in the **UI**. Refactor **Team Invitation** and any **role selection/display** to use **value = ID**, **label = formatted text**. Handle **unknown** / **legacy** role strings without breaking the app.

## must_haves

- [ ] **`RoleId`** (union or const-driven type) matches the **nine** required identifiers exactly.
- [ ] **`RoleRegistryService`** (or equivalent) exposes: all role options for dropdowns, **`labelOf(id)`**, **`isKnown(id)`**, **`normalize(id | null)`** → known `RoleId` or `null`, **`unknownLabel`** constant for fallback.
- [ ] **No** display strings in **POST/PUT** bodies for role fields — only **IDs**.
- [ ] **Team invitation** `<select>`: **`[value]` = ID**, visible text = label; **`TeamMember.role`** documents **stores ID** (or rename to **`roleId`** if low churn).
- [ ] **Completion / review** shows **labels** (pipe or mapper), not raw IDs in user-facing text.
- [ ] **Unknown role** from API: show **“Unknown Role”** (or similar) + **debug/warn** log with raw value.
- [ ] **`roleGuard`**: document that **`allowedRoles`** are **canonical IDs**; update **route** usages if currently wrong.
- [ ] **`ng build`** passes.
