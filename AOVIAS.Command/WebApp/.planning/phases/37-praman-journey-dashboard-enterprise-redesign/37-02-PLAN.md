# 37-02: Reusable UI components and token-compliant styling

## Objective
Build reusable enterprise-grade dashboard components (`journey-card`, `recommendation-panel`, `action-bar`, `metric-card`, `chart-card`) with OnPush change detection, Input/Output APIs, and strict token-based SCSS implementation.

## Tasks

<task id="01" name="Implement journey-card component">
### Journey mode selector card
- Build `journey-card` with inputs for icon/title/description/status/progress/locked tooltip.
- Add output for select click.
- States:
  - active: emphasized border/elevation
  - inactive: muted clickable
  - locked: disabled + lock affordance + tooltip
- Ensure 2-line description clamp and keyboard activation.

**must_haves:**
- ARIA labels include mode + state.
- Active card optionally renders progress bar only when applicable.
</task>

<task id="02" name="Implement recommendation-panel and action-bar">
### Smart recommendation + primary actions
- `recommendation-panel`:
  - title + message + primary/secondary actions
  - metadata row (high-risk count, last activity)
  - emits action events only
- `action-bar`:
  - exactly 3 actions (primary, secondary, danger)
  - responsive horizontal -> stacked mobile behavior
  - visual hierarchy enforces one primary CTA.

**must_haves:**
- No API/store logic in these components.
- Button variants map to semantic tokens, not raw classes with hardcoded colors.
</task>

<task id="03" name="Implement metric-card and chart-card wrappers">
### KPI and chart frame components
- `metric-card`:
  - icon, label, value, optional trend indicator.
- `chart-card`:
  - title, time filter slot/input, content projection for chart canvas
  - click output for drilldown intent
  - tooltip-ready container semantics.
- Maintain consistent card height rhythm and spacing tokens.

**must_haves:**
- Visual consistency across all cards in light and dark themes.
- Reusable API suitable for other dashboard pages.
</task>

<task id="04" name="Token compliance and style migration">
### Enforce no hardcoded visual values
- Implement SCSS using only token variables from `src/styles/tokens/*`.
- Remove hardcoded colors/pixels from new component SCSS and touched page SCSS.
- If missing semantic tokens are discovered, add them centrally before use.

**must_haves:**
- No inline style attributes in templates.
- No raw hex literals in touched component/page SCSS.
</task>

## Verification criteria
- [ ] All 5 required reusable components exist and are used by Journey page composition.
- [ ] `ChangeDetectionStrategy.OnPush` is used in each new component.
- [ ] Inputs/Outputs are explicit and no component performs business logic.
- [ ] Styling in touched files is token-only and theme-safe.

## must_haves (goal-backward)
- Enterprise UI layer is modular, reusable, and cleanly separated from state.
- Journey mode and action UX are immediately actionable and accessible.
- Design system conformance is enforceable during future iteration.
