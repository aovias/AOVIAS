# 37-01: Journey dashboard reset, contracts, and container shell

## Objective
Remove the existing Journey dashboard UI composition and establish a brand new container structure and typed view-model contracts for the enterprise PRAMAN Journey dashboard, preserving workflow context and keeping business/state logic outside reusable presentation components.

## Tasks

<task id="01" name="Remove old journey dashboard composition">
### Replace page composition with a clean new shell
- Refactor `journey.component.*` to a new top-level section order:
  1) Header
  2) Journey Mode Selector
  3) Recommendation Panel
  4) Primary Action Bar
  5) Metrics Overview
  6) Insights & Charts
- Remove legacy UI blocks/classes tied to prior layout patterns.
- Keep route/module boundaries unchanged so lazy loading remains intact.

**must_haves:**
- No old layout section survives in template.
- New shell is grid-based and sectionized for reusable child components.
</task>

<task id="02" name="Create typed dashboard view models">
### Add/normalize models for dashboard sections
- Create or update models for:
  - `JourneyModeCardVm`
  - `RecommendationPanelVm`
  - `PrimaryActionVm`
  - `MetricCardVm`
  - `ChartCardVm`
- Keep these models UI-focused and serializable.
- Keep data derivation in container/store selectors, not in child components.

**must_haves:**
- No `any` in dashboard view models.
- Locked/inactive/active mode states are explicit types.
</task>

<task id="03" name="Container orchestration and events">
### Wire data + events at container level only
- In `journey.component.ts`, map store/domain state to new dashboard VMs.
- Handle child outputs centrally:
  - mode selection
  - recommendation actions
  - action bar clicks
  - chart click intents (future drill-down hooks)
- Ensure read-only/locked constraints are enforced by state, not duplicated in child components.

**must_haves:**
- Child components remain presentational.
- Container owns interaction-to-store mapping.
</task>

<task id="04" name="Responsive 12-column layout shell">
### Define section layout contract
- Implement a 12-column responsive layout for page sections:
  - desktop: full structure with multi-column cards/charts
  - tablet/mobile: stacked flow preserving section priority
- Use only tokenized spacing and radii.

**must_haves:**
- No raw px spacing values.
- Mobile order remains identical to requested top-to-bottom section order.
</task>

## Verification criteria
- [ ] `journey.component.html` reflects only the new six-section structure.
- [ ] View models exist for all section component contracts.
- [ ] Container is the only place with business/state orchestration.
- [ ] Module remains lazy-loaded and build passes.

## must_haves (goal-backward)
- Full reset of Journey dashboard UI structure is complete.
- New page shell is ready for enterprise component composition.
- Workflow context (Chapter -> Standard -> OE) remains available for actions/drilldown.
