# Plan 28-01: User-scoped onboarding storage + lifecycle cleanup

## Objective

Eliminate **cross-user onboarding data leakage** on shared browsers by binding persisted wizard state to **`userId`**, clearing state on **logout** and **user change**, and safely initializing the wizard when stored data is absent, invalid, or owned by another user.

## must_haves

- [ ] **`sessionStorage` keys** for AI wizard + signup onboarding are **namespaced** with current **`userId`**, or equivalent **owner field** validated on every load.
- [ ] **`AuthService.logout()`** clears **all** onboarding persisted state and **in-memory** wizard/signup store defaults (via a single coordinator or explicit calls).
- [ ] **After successful login** (and optionally after **refresh** if `userId` changes): if identity **changed**, purge stale onboarding data **before** navigating to onboarding.
- [ ] **Load from storage** only when **`getUserId()`** matches stored owner; otherwise **ignore** and use **fresh** defaults.
- [ ] **No `userId`:** do **not** restore cross-user drafts; start **empty** / defaults.
- [ ] **Corrupt JSON / schema:** catch and reset safely (reuse existing `normalizeLoaded` patterns where applicable).
- [ ] **`ng build`** passes.
