# Phase 48 — Plan 01: Central OperationalMode UI policy + store wiring

## Phase goal (backward)

After this wave, the codebase has a **single source of truth** for “what the Journey UI may show/do” per **`OperationalMode`**, exposed as typed **pure functions** + optional **computed selectors** on `JourneyWorkspaceStore`, so later waves only **bind** templates to policy output (no ad-hoc mode switches in components).

## must_haves

- [ ] New module e.g. `journey-operational-mode.policy.ts` exporting a stable **`JourneyOperationalModeUiPolicy`** (or split by concern with one facade) covering at minimum: **dashboard** (progress bar kind, high-risk action visibility), **metrics visibility** (four flags), **wizard** (step enablement + read-only), **context panel** (evidence/tasks visibility + disabled), **execution** section toggles (placeholders with `TODO` wire-up in 48-03 if needed).
- [ ] Policy is **pure**: `(mode: OperationalMode, ctx: …) => policy` where `ctx` holds snapshot-derived bits (e.g. `readOnly`, mock progression flags)—**no** Angular imports inside the pure file.
- [ ] `JourneyWorkspaceStore` exposes **readonly computed** e.g. `operationalModeUi()` delegating to policy with current `lifecycleMode()` + minimal context.
- [ ] `ng build` passes.
