# Phase 40 — Wave 1: Page intro + Journey mode cards (reference parity)

## Goal (backward from success)

The **Journey** dashboard (`/app/journey`) opens with **left-aligned** page copy:

- **Title:** `Select Your Journey Mode`
- **Subtitle:** `Choose the audit phase to focus on`

**Journey mode cards** match the reference: **four cards in one row on desktop**, **Lucide icons** (not single-letter placeholders), **strong active state** (primary border + soft glow via tokens), **clear inactive vs locked** (muted surfaces), **larger title typography**, status treatment aligned with reference. All styling uses **`DESIGN_RULES.md`** + `src/styles/tokens/*` (no raw hex in feature SCSS).

## must_haves

- [ ] `journey.component.html`: semantic header region (`<header>` or `<div role="region">`) with `h1` + subtitle; appears **above** `journey-mode-grid` when data loaded.
- [ ] `journey.component.scss`: token-based spacing/typography for intro; does not reintroduce old global `journey-header` chrome.
- [ ] **Desktop layout:** mode cards display **four abreast** at reference breakpoints — adjust grid (`repeat(4, minmax(0,1fr))` or equivalent) and media queries so **stacking only** below defined tablet/mobile widths (document breakpoint values).
- [ ] `JourneyModeCardVm` extended with a stable **icon key** (or similar) per lifecycle mode; `buildModeCards()` supplies it.
- [ ] `journey-card`: render **NgIcon + Lucide** (same stack as `execution-action-panel`) instead of text `icon` only; map keys to icons (check, search, lock, etc.).
- [ ] Active card: **`--color-brand-primary`** border + **`box-shadow`** “glow” using `color-mix` / theme tokens; locked/inactive visually distinct per gap doc.
- [ ] Progress bar on selected mode remains functional; styling matches reference emphasis where feasible.
- [ ] Build passes; a11y: heading order logical (`h1` once per page content).

## Non-goals

- No new backend/API contracts.
- No global app header / sidebar changes.
