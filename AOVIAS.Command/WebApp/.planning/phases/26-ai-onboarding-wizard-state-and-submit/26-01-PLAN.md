# Plan 26-01: AI onboarding wizard — centralized state, persistence, team↔department, submit

## Objective

Refactor the **AI Setup Assistant** (`/onboarding` → `AiSetupAssistantComponent`) so that:

- There is a **single source of truth** for wizard data across **Hospital Profile → Frameworks → Assessment → Team → Review/Complete**.
- State **persists** across step navigation and **browser refresh** (same tab session) where feasible.
- **Team Invitation** department choices are **only** departments selected in **Hospital Profile**.
- **Review** shows a **consistent** summary of all sections.
- **Final CTA** calls **`POST /onboarding/onboard`** with a **typed** payload matching the backend; failures allow **retry** without losing data.

**Note:** Existing wizard has **Welcome** as step 1 and **Completion** as step 6 — the “five steps” in requirements map to **profile, frameworks, assessment, team, review** (steps **2–6** in current UI).

## must_haves

- [ ] Dedicated **store/service** holds full wizard state; **`AiSetupAssistantComponent`** reads/writes through it (not ad-hoc duplicate fields).
- [ ] **sessionStorage** (or equivalent) persistence for AI wizard under a **distinct key** from signup `onboarding_state` (e.g. `ai_onboarding_wizard_v1`).
- [ ] **`OnboardingService.submitOnboard(request)`** → **`POST /onboarding/onboard`** with interfaces in **`onboard-submit-request.model.ts`** (adjust names to match real API).
- [ ] **Team step**: department **select** bound to **allowed departments** from profile; **duplicate email** prevention; clear empty-state if **no** departments selected.
- [ ] **Completion**: expanded summary + **submit** flow with loading/error/retry.
- [ ] **Step validation** before advancing (minimum: required fields per step as today, extended for email uniqueness and department rules).
- [ ] **`ng build`** passes.
