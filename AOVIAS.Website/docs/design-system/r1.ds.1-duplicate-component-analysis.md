# R1.DS.1 — Duplicate Component Analysis

**Date:** 2026-07-21  
**Constraint:** Document recommendations only — **do not merge or rename code** in this sprint

---

## Summary

| Cluster | Semantic overlap | Recommendation |
| --- | --- | --- |
| Content cards | High | Future unify under Card recipe + content variants |
| Heroes | Medium | Keep dual APIs; share token roles |
| Empty states | High | Prefer system-states; deprecate primitive for page use |
| Atmosphere | Medium | Alias feature atmosphere to Brand Atmosphere roles |
| CTAs | Medium | Button as base; MarketingCtaLink / EnterpriseCta as recipes |
| Logo grids | Medium | LogoCloud vs CustomerLogoGrid — shared grid recipe |
| FAQ | Low–Medium | Faq vs PricingFaq — shared accordion recipe |
| Timelines | Low | Timeline vs TrustTimeline — shared vertical timeline |
| Architecture diagrams | Low | Brand diagram vs Product ArchitectureDiagramBlock wrapper |

---

## 1. Content cards

**Members:** `FeatureCard`, `ValueCard`, `PrincipleCard`, `ArticleCard`, primitive `Card`

| Aspect | Notes |
| --- | --- |
| Shared role | Elevated content tile with title, body, optional icon/media, optional link |
| Distinct props | Article has category/date/reading time; Principle often numbered; Feature often icon-led |
| Risk if forced merge now | Breaks marketing/content APIs mid-release |

**Recommendation (post–R1.DS.2):** Introduce a single **Content Card** recipe with variants (`feature` | `value` | `principle` | `article`). Keep thin wrappers for domain DX. Tokenize once via `color.surface`, `type.heading.h3`, `space.card-padding`, `elevation.raised`.

---

## 2. Dual heroes

**Members:** `Hero` (marketing), `ProductHero`

| Aspect | Notes |
| --- | --- |
| Shared role | First-viewport brand + headline + CTA + media plane |
| Distinct | ProductHero binds MediaSlot / product CTAs; marketing Hero is freer |
| Atmosphere | Both can sit on SectionSurface + BrandAtmosphere |

**Recommendation:** Retain both components. Align recipes and token roles. Avoid a third hero abstraction until product/marketing APIs stabilize.

---

## 3. Empty states

**Members:** `primitives/EmptyState`, `system-states/EmptyState`, `SearchEmptyState`, `NoResults`

| Aspect | Notes |
| --- | --- |
| Shared role | Centered message + optional illustration + actions |
| Distinct | Search/NoResults specialize copy and actions |

**Recommendation:** Treat **system-states** as canonical for pages. Primitive EmptyState → atom or deprecate for page composition after token pass. Document import path preference in naming standard.

---

## 4. Atmosphere

**Members:** `BrandAtmosphere`, Home Hero Atmosphere (feature-local)

| Aspect | Notes |
| --- | --- |
| Shared role | Decorative brand backdrop / motion field behind heroes |
| Distinct | Home may tune density for homepage storytelling |

**Recommendation:** Same token roles (`color.brand-atmosphere`, `motion.*`, `blur.*`). Optionally re-export home atmosphere as BrandAtmosphere variant later — not required for R1.DS.2.

---

## 5. CTA cluster

**Members:** `Button`, `MarketingCtaLink`, `EnterpriseCta`, CTA slots inside `CtaSection` / `Hero` / `ProductHero`

| Aspect | Notes |
| --- | --- |
| Shared role | Primary conversion action |
| Distinct | MarketingCtaLink is link-styled CTA; EnterpriseCta is pricing/sales band |

**Recommendation:** Button owns interactive variants. MarketingCtaLink / EnterpriseCta are **recipes** over Link/Button + layout — not separate color systems.

---

## 6. Logo / proof grids

**Members:** `LogoCloud`, `CustomerLogoGrid`

**Recommendation:** Shared **Logo Grid** recipe; keep domain names for trust vs marketing copy.

---

## 7. FAQ

**Members:** `Faq`, `PricingFaq`

**Recommendation:** Shared accordion/disclosure recipe; PricingFaq may bind pricing content models only.

---

## 8. Timeline

**Members:** `Timeline`, `TrustTimeline`

**Recommendation:** Shared vertical timeline recipe; domain data shapes differ.

---

## 9. Architecture diagram

**Members:** `ArchitectureDiagram` (brand), `ArchitectureDiagramBlock` (product)

**Recommendation:** Block is a product section wrapper — keep; single visual language via brand diagram tokens.

---

## Low-use / orphan-adjacent exports

| Export | Observation | Action |
| --- | --- | --- |
| `InstitutionalScene` | Weak call-site density | Keep in registry; do not expand until needed |
| `LeadershipMark` | Weak call-site density | Same |
| Primitive vs layout duplicate `Container`/`Section`/`Grid`/`Stack` | Intentional re-exports | Prefer `components/layout` or primitives consistently per layer |

These are **not** unclassified orphans — they are classified Media roles with low usage.

## Consolidation gate (future sprints)

Do **not** consolidate in R1.DS.1 or R1.DS.2. Consolidation requires:

1. Semantic color + type roles applied to shared shells
2. Visual parity checklist across all variants
3. Explicit migration PR (out of scope here)
