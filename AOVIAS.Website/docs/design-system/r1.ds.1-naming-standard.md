# R1.DS.1 — Naming Standard

**Date:** 2026-07-21  
**Purpose:** Map code identifiers → canonical taxonomy names; rules for future work

---

## Principles

1. **Taxonomy name** = human-readable Title Case role used in DS docs and token recipes.
2. **Code name** = PascalCase React export; do not rename in R1.DS.1.
3. **Token role** = dotted semantic path (`color.surface`, `type.heading.h1`) — never raw values in taxonomy docs.
4. Prefer **role clarity** over folder fidelity (`FeatureCard` → Feature Card under Cards + Marketing).

---

## Mapping rules

| Pattern | Taxonomy form | Example |
| --- | --- | --- |
| `FooBar` component | Foo Bar | `SectionSurface` → Section Surface |
| `*Cta*` | CTA (acronym) | `MarketingCtaLink` → Marketing CTA Link |
| `*Faq` | FAQ | `PricingFaq` → Pricing FAQ |
| Product console names | keep product noun | `DashboardConsole` → Dashboard Console |
| System state + primitive clash | qualify | Primitive Empty State vs System Empty State |
| Layout shell | `… Layout` | `MarketingLayout` → Marketing Layout |

## File / folder conventions (documentation)

- Sprint docs: `r1.ds.1-<kebab-topic>.md`
- API guides: keep existing `*-components.md` / `*-api.md` names
- Do not invent parallel folders under `docs/design-system/` for taxonomy (stay flat with prefix)

---

## Import preference (guidance only)

When two exports share a role:

1. Prefer **domain barrel** used by pages (`system-states` for page empties).
2. Prefer **layout** barrel for page chrome; primitives for atomic composition.
3. Prefer **Brand Atmosphere** roles for any hero backdrop naming in docs.

---

## Forbidden in R1.DS.1 docs

- Hex / rgb / hsl values
- Pixel / rem scales as assigned standards
- Renaming recommendations presented as completed work
- Emoji in taxonomy names
