## Release 2 integration steps

1. Implement a real adapter file per provider (e.g. `adapters/google-analytics-provider.ts`).
2. Map `TelemetryEvent` → provider payload (never reverse: UI → provider).
3. Gate init on `consent.analytics` (and `marketing` where required).
4. Register via `createTelemetryClient({ providers: [...] })` / config list.
5. Keep mock provider in non-production for local inspection.
6. Optional: OTLP exporter for Command/Studio parity using the same Event/Span/Context model.

## Consent mapping

| Consent | Providers typically gated |
| --- | --- |
| functional | Always allowed (errors with `consent: none`) |
| analytics | GA, PostHog, Mixpanel, Plausible, Clarity, OTel |
| marketing | Newsletter / advertising pixels (future) |
| preferences | Preference storage only (future UI) |

## Do not

- Import provider SDKs in pages or feature components
- Enable `NEXT_PUBLIC_FF_ANALYTICS` in production until adapters + consent UI exist
