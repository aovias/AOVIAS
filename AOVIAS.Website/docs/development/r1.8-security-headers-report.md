# R1.8 — Security Headers Report

**Date:** 2026-07-20  
**Status:** Complete

---

## Application headers (`next.config.ts`)

| Header | Value / notes |
| --- | --- |
| Content-Security-Policy | Baseline App Router CSP; prod adds `upgrade-insecure-requests` |
| Strict-Transport-Security | Prod only: 2y, includeSubDomains, preload |
| X-Content-Type-Options | `nosniff` |
| Referrer-Policy | `strict-origin-when-cross-origin` |
| Permissions-Policy | camera/mic/geo/payment/usb disabled |
| X-Frame-Options | `DENY` (with CSP `frame-ancestors 'none'`) |
| Cross-Origin-Opener-Policy | `same-origin` |
| Cross-Origin-Resource-Policy | `same-origin` |
| X-Permitted-Cross-Domain-Policies | `none` |
| X-DNS-Prefetch-Control | `on` |
| X-Powered-By | Removed (`poweredByHeader: false`) |

## Edge (nginx profile)

Also sets nosniff, referrer-policy, frame deny for defense in depth.

## Notes

CSP still allows `'unsafe-inline'` / `'unsafe-eval'` for Next/next-themes — tighten with nonces in a future hardening sprint. Do not weaken headers for convenience.
