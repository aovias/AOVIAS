# R1.7 — Telemetry Architecture Overview

**Date:** 2026-07-20  
**Status:** Complete  
**Deployment:** Not started

---

## Purpose

Prepare the AOVIAS public website for Release 2 analytics without live collectors, page-level provider coupling, or UI behaviour changes.

## Principles

| Principle | Application |
| --- | --- |
| Dependency inversion | UI → `TelemetryClient` → `AnalyticsProvider` |
| Provider abstraction | Mock today; GA / Clarity / PostHog / … tomorrow |
| Environment isolation | `NEXT_PUBLIC_FF_ANALYTICS` default **false** |
| Consent readiness | Injectable `ConsentState` (no consent UI) |
| OpenTelemetry alignment | Event, Trace, Span, Context, Attributes |

## Structure

```
apps/website/src/telemetry/
  core/           # OTel-shaped types + TelemetryClient / AnalyticsProvider
  registry/       # Event catalog, names, validation
  events/         # Taxonomy + conversion contracts
  providers/      # Stub factories for future sinks
  mocks/          # In-memory mock provider (only R1 sink)
  adapters/       # Client composition + singleton registry
  consent/        # Consent categories + gating
  context/        # React TelemetryProvider
  hooks/          # useTelemetry, usePageView, useTrackEvent
  instrumentation/# PageViewTracker, section mapping
  config/         # resolveTelemetryConfig
```

## Runtime path

```
AppProviders → TelemetryProvider
  → routes (unchanged)
  → TelemetryBootstrap → PageViewTracker
  → ErrorBoundary → trackError (consent: none)
  → Contact form adapters → trackConversion (gated)
```

## Active in R1

- Mock provider only (`transmits: false`)
- Instrumentation mounted but **inactive** unless flag + analytics consent
- Default consent: analytics/marketing **off**

## Inactive / deferred

- Real provider SDKs and scripts
- Consent banner UI
- Network export / OpenTelemetry collector
