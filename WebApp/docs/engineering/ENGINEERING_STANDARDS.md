# AOVIAS COMMAND — Engineering Standards

> **Status:** Sprint INF-02, initial edition.
> Every rule here exists because it was violated and caused a real, observed
> failure. Nothing is aspirational. Where a rule has no incident behind it yet,
> it is marked _(unproven)_ so future contributors know it has not been tested
> against reality.

---

## 1. Database Migrations

### 1.1 Never hand-write a migration

**Rule.** A migration is created by `dotnet ef migrations add <Name>`. If you must
hand-edit the generated file, edit it *after* generation — never author the
`.cs` file yourself.

**Why.** A hand-written migration has no `.Designer.cs` and does **not**
regenerate `ComplianceDbContextModelSnapshot.cs`. The snapshot then no longer
describes the database, and every subsequent migration tries to re-create
objects that already exist.

**Evidence.** ComplianceService has 47 migrations, **16 of them hand-written**.
The snapshot was last correctly regenerated by
`20260626075821_Sprint17_ClinicalIndicators`; ten hand-written migrations landed
after it. The committed snapshot is 1,883 lines — regenerating it from the
current model produces 7,071. Roughly three quarters of the model is missing
from the snapshot.

### 1.2 `migrations remove` is unsafe until the snapshot is reconciled

**Rule.** Do not run `dotnet ef migrations remove` in ComplianceService until
INF-01 recovery is complete. Delete the migration files manually and restore the
snapshot from git instead.

**Why.** `remove` reverts the snapshot to the *previous migration's* Designer
file. When the previous migration is hand-written, there is no Designer to
revert to, and EF silently reverts to a broken state.

**Evidence.** Observed directly during Stage 5: after `migrations remove`, a
freshly generated migration attempted `CreateTable` for **every table in the
system**, not the two expected. The snapshot had to be restored from git.

### 1.3 A migration has exactly one purpose

**Rule.** Before committing, read the generated migration. It must contain only
the objects your change touches. If unrelated tables appear, stop — that is
snapshot drift, not your change.

**Evidence.** A Stage 5 `AuditProgram` migration silently swept in
`DashboardProjections` and `GovernanceTraceLinks`. Both tables already existed;
applying it would have failed at deploy time.

### 1.4 Back up before touching `__EFMigrationsHistory`

**Rule.** Any reconciliation that inserts or deletes migration-history rows
requires a database backup first, and must be done in a single reviewed change.

## 2. Angular Components

### 2.1 Multi-component files must use `styleUrl`

**Rule.** A `.ts` file declaring more than one `@Component` uses `styleUrl` with
a sibling `.scss`. Do not use inline `styles: [...]` there.

**Why.** Angular's AOT compiler resolves `styles` **statically**. A `const`
reference, a template-literal concatenation, or (observed) certain inline blocks
in multi-component files fail with:

```
FatalDiagnosticError: Code: 1010,
Message: Failed to resolve styles at position 1 to a string
```

The error names **no file**, which makes it expensive to locate — it has to be
bisected.

**Evidence.** Cost roughly an hour across two occurrences in Stage 1.2 and 1.3
(`audit-context-sections.ts`, `workspace-states.ts`). Both fixed by extracting
to `.scss`.

### 2.2 `tsc --noEmit` is not a sufficient gate

**Rule.** Verify Angular work with `ng build`, never `tsc` alone.

**Why.** `tsc` does not typecheck Angular templates. A template can reference a
property that does not exist and `tsc` passes clean.

**Evidence.** `rec.summary` was written where the field is `rec.description`.
`tsc --noEmit` reported no errors; `ng build` caught it.

### 2.3 Boolean inputs require explicit binding

**Rule.** Write `[wide]="true"`, not `wide`. A bare attribute passes the string
`""`, not `true`.

**Evidence.** Two build failures in Stage 4 (`TS2322: Type 'string' is not
assignable to type 'boolean'`).

### 2.4 Verify field names against the model before use

**Rule.** Read the interface before referencing its fields. Do not infer names.

**Evidence.** Six invented APIs caught during Stage 1.1 alone:
`promoteSelectedToCapa` (actual: `promoteFinding`), `dashboard.openCount`
(`openFindings`), `comment.body` (`content`), `history.changedAt`/`changedBy`
(`occurredAt`/`actorType`), `result.readinessScore` (`score`), and
`focusOwnerAssignment` (does not exist).

## 3. Navigation & Routing

### 3.1 Legacy redirects are load-bearing — do not delete them

**Rule.** Redirect routes preserved for backward compatibility must not be
removed. To retire a legacy path, repoint **internal** links to the canonical
route and leave the redirect as a compatibility layer for bookmarks and external
deep links.

**Evidence.** A Stage 2 instruction to "remove legacy redirects" would have
broken **14 in-app references** to `/app/auditor/**` plus every user bookmark.
Repointing 16 files to canonical routes achieved the intent with no breakage.

### 3.2 Repointing a route means auditing path-matching code

**Rule.** After changing a route, grep for the old path in services that match
on URL strings.

**Evidence.** `copilot-navigation-bridge.service.ts` mapped
`/audit/corrective-actions` to an AI context and would have silently stopped
matching once links moved to `/audit/capa`.

### 3.3 Distinguish navigation *surfaces* before calling something duplication

**Rule.** Entries on `SIDEBAR`, `BOTTOM` and `HEADER` are different surfaces. The
same route appearing on two surfaces is not drift.

**Evidence.** `workspace.bottom.findings` was wrongly flagged as duplicate
navigation in a review; it is the mobile bottom bar and is legitimate.

## 4. Accessibility

### 4.1 Every interactive surface carries ARIA

**Rule.** Tables, tab strips, modals, drawers and status indicators require
explicit roles and labels. New components ship with them; this is not a
follow-up task.

**Evidence.** All **eight** Audit page components contain zero `aria-*` or
`role` attributes. For a healthcare compliance product this is a procurement
risk — public-sector and large private health systems routinely require a VPAT
or WCAG 2.1 AA statement.

**Current state.** The workspace components added in Stages 1.1–1.3 do carry
ARIA and establish the pattern. The eight pre-existing pages do not.

## 5. Data & Persistence

### 5.1 Business data does not live in browser storage

**Rule.** `localStorage` / `sessionStorage` hold **user preferences** (panel
open, last tab, pinned state). Shared organisational data requires a server API.

**Why.** Browser storage is per-browser and per-device. Data stored there is
invisible to teammates, lost on cache clear, and absent from any audit trail.

**Evidence.** `audit-prep-template.service.ts` stores audit prep templates —
shared organisational assets — in `localStorage`. The file is honestly labelled
as temporary, but it quietly breaks the collaboration model the rest of the
product assumes.

## 6. Verification & Definition of Done

### 6.1 UI work is not done until it has been rendered

**Rule.** A change to a component's template or styles requires visual
confirmation before it is called complete. Build, lint and unit tests verify
logic; they do not verify layout, focus behaviour, or responsive reflow.

**Evidence.** Eight stages of workspace UI — context drawer, role dashboard,
standardised loading/empty/error states, Executive Intelligence — were built and
verified by build, lint and 163 unit tests, but **never rendered**. Seeded demo
users have no `PasswordHash` and the available test accounts lack the tenant
claims needed to clear the onboarding guard.

**Consequence.** A layout defect shipped undetected and was only found from a
user screenshot: the context panel sized to its own content instead of filling
the column, because a percentage height resolved against an auto-height parent.
No test could have caught it.

**Required.** The development environment must provide at least one login with
real tenant claims. Until it does, treat all UI work as unverified.

### 6.2 State the verification boundary explicitly

**Rule.** When reporting completion, say what was verified and what was not.
"Tests pass" and "it works" are different claims.

## 8. Not Yet Established _(unproven)_

Declared for honesty — these are **not** in place, and INF-02 asked for them:

- Automated architecture conformance (layer boundaries, dependency direction,
  circular-dependency detection)
- Static analysis gates that fail the build
- API contract governance and generated OpenAPI
- Coverage thresholds for critical business logic
- Performance budgets (bundle size, API latency, query performance)
- A completed security review
- CI quality gates of any kind

The single highest-value CI gate, once INF-01 recovery lands, is **migration
validation**: generate a migration in CI and fail the build if it is not empty.
That one check would have prevented the drift documented in §1.
