# Phase 49 — Plan 01: API DTOs, JourneyDataService, and mappers aligned to spec

## Phase goal (backward)

After this wave, **`JourneyDataService`** exposes typed methods for every **core** Journey endpoint in `journey-module-api-specification.md` (relative to `environment.apiBaseUrl`), with DTOs matching **`JourneySessionDto`**, **`JourneyDashboardDto`**, **`JourneyChaptersIndexDto`**, **`ComplianceStandardDto[]`**, **`ObjectiveElementDto`**, **`PatchObjectiveElementRequest`/`Response`**, evidence register/delete/list, and **`PATCH …/session/operational-mode`**. Mappers produce existing **domain** types (`JourneyWorkspaceSnapshot`, `JourneyChapter`, `ComplianceStandard`, `ObjectiveElement`) so Wave 2 can swap the store data source without template rewrites.

## must_haves

- [ ] All paths use **`/journeys/${journeyId}/…`** (no legacy `/Journeys/workspace` for primary flow); document **`v1` vs `v1.0`** check in a one-line comment near base path constant.
- [ ] `GET …/chapters` maps **`data.items`** wrapper to `JourneyChapter[]` (or intermediate DTO).
- [ ] `PatchObjectiveElementBody` extended with optional **`version`** for optimistic concurrency.
- [ ] Evidence **POST** success mapped from **`{ evidenceId }`** (refetch OE in Wave 2).
- [ ] `journey-api.model.ts` includes session fields: **`snapshotReadOnly`**, **`modeProgression`**, **`catalog`**, dashboard **`accreditationReadinessPercent`**.
- [ ] `ng build` passes.
