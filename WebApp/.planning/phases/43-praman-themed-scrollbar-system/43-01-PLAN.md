# Plan 01 — Scrollbar design specification + token catalog

## Goal (phase)

Establish the **authoritative UX and visual design** for PRAMAN’s themed scrollbar system: global behavior, **mandatory design tokens** (no hardcoded literals), interaction states, context variants, responsive rules, accessibility expectations, and micro-interactions — aligned with enterprise dark-first UI and **light/dark** parity.

## must_haves

- [ ] Written **global behavior** definition: idle minimalism, hover/drag discoverability, focus-visible affordance, auto-visibility (subtle when idle, clearer on interaction).
- [ ] **Token catalog** listing every scrollbar-related semantic: track, thumb (default / hover / active), optional thumb border or inset, width (desktop vs tablet), radius, idle opacity vs hover opacity, active accent linkage to brand tokens, **motion durations** referencing foundation motion tokens (or newly introduced scrollbar-specific motion aliases that reference existing `--duration-*` / `--easing-*` patterns if present).
- [ ] **Four states** specified: default (idle), hover, active (dragging), focus (keyboard / focus-visible).
- [ ] **Context variants** defined: primary scroll surfaces (large content), secondary panels (side panels, filters), dense lists (tables, OE lists, evidence lists), timeline-style views — each with **one** clear rule for thumb visibility vs subtlety (no ad-hoc per-module styles).
- [ ] **Responsive rules:** desktop = thin; tablet = slightly wider for touch; mobile = native scrolling, **no** forced custom scrollbar treatment that degrades touch UX.
- [ ] **Accessibility:** keyboard scrolling supported; focus indication visible; active/drag/focus states meet **contrast** expectations relative to adjacent surfaces (documented as token relationships, not raw ratios in feature code).
- [ ] **Explicit non-goals:** no thick bars, no bright decorative colors, no sharp edges, no JS-heavy scrollbar libraries for default behavior.

## Tasks

### Task 1 — Global behavior and principles

```xml
<task id="43-01-t1-behavior">
  <title>Document global scrollbar behavior</title>
  <steps>
    <step>Describe default (idle) appearance: low visual weight, thumb blends with surface/track using token-derived muted colors.</step>
    <step>Describe hover: thumb becomes more visible; transition timing uses tokenized motion (no ad-hoc ms in components).</step>
    <step>Describe active/drag: thumb uses brand-aligned accent via existing primary/semantic tokens; clear feedback without dominating layout.</step>
    <step>Describe focus-visible: scroll container or focused descendant shows visible focus ring/outline per existing focus token patterns; scrollbar thumb may increase contrast in sync with focus context.</step>
    <step>Describe auto-visibility: scrollbars remain subtle until pointer hover over scroll region, scroll gesture, or keyboard focus into scrollable area — without hiding functionality from assistive tech.</step>
    <step>State consistency rule: one system across modules; only **context variants** (token sets) differ.</step>
  </steps>
  <verify>Design review: behavior doc covers all four states + auto-visibility + consistency.</verify>
</task>
```
