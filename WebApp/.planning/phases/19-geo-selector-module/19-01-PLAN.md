# Plan 19-01: Geo configuration + GeoSelectorService (India-first, cached)

## Objective

Create a configuration-driven geo layer and a centralized, cached client-side `GeoSelectorService` that provides states and cities using the `country-state-city` npm package, defaulting to India (`IN`) while remaining future-ready for multi-country rollout.

    2. Ensure the dependency is recorded in `package.json` and lockfile.
  </action>
  <verify>
    - `country-state-city` appears under `dependencies`
    - `npm run build` succeeds
  </verify>
  <done>country-state-city dependency added</done>
</task>

<task>
  <name>Add GeoConfig injection token (config-driven)</name>
  <files>src/app/core/config/geo.config.ts, src/app/app.config.ts</files>
  <action>
    1. Create `GeoConfig` interface containing:
       - `defaultCountryCode: string` (default 'IN')
       - `enabledCountryCodes: string[]` (default ['IN'])
       - `allowCountrySelection: boolean` (default false)
       - `cityAutocompleteMinChars: number` (default 2)
       - `maxCityOptions: number` (default 200)
    2. Export `GEO_CONFIG` InjectionToken&lt;GeoConfig&gt; and `DEFAULT_GEO_CONFIG`.
    3. Provide the config in `app.config.ts` so it can be overridden later without code changes.
  </action>
  <verify>
    - `GEO_CONFIG` is injectable app-wide
    - Defaults are India-first (IN only)
    - No component hardcodes 'IN' outside config consumption
  </verify>
  <done>Geo config layer exists and is injectable</done>
</task>

<task>
  <name>Create shared geo models</name>
  <files>src/app/shared/models/geo.models.ts</files>
  <action>
    1. Create interfaces:
       - `GeoCountryOption { code: string; name: string }`
       - `GeoStateOption { code: string; name: string }` (code = ISO state code)
       - `GeoCityOption { name: string }`
       - `GeoSelectionValue { countryCode: string; stateCode: string; cityName: string }`
  </action>
  <verify>
    - Types are reusable across features and shared UI
  </verify>
  <done>Shared geo types created</done>
</task>

<task>
  <name>Implement GeoSelectorService (cached, India-first)</name>
  <files>src/app/shared/services/geo-selector.service.ts</files>
  <action>
    1. Create `GeoSelectorService` with `@Injectable({ providedIn: 'root' })`.
    2. Inject `GEO_CONFIG`.
    3. Wrap `country-state-city` access behind methods:
       - `getActiveCountries(): GeoCountryOption[]` (based on `enabledCountryCodes`)
       - `getStates(countryCode?: string): GeoStateOption[]` (defaults to config default; cached per country; sorted by name)
       - `getCities(stateCode: string, countryCode?: string): GeoCityOption[]` (cached per `${countryCode}:${stateCode}`; sorted by name)
    4. Cache strategy:
       - In-memory Maps for states and cities
       - Cities loaded only on-demand per state
    5. Defensive behavior:
       - If countryCode not enabled, return empty list
       - If stateCode invalid/unrecognized, return empty city list
  </action>
  <verify>
    - No backend calls or HttpClient usage
    - Repeated calls do not re-run heavy lookups (cache hit)
    - States list is stable and sorted
    - Cities are only loaded after state selection
  </verify>
  <done>GeoSelectorService provides cached state/city lists from npm package</done>
</task>
