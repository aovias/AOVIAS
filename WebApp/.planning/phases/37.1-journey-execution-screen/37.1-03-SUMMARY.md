## Implementation Notes

### 1) Right context/action panel
- Upgraded `execution-action-panel` into a presentational action surface with:
  - Selected OE detail section
  - Primary actions (`Start/Resume Journey`, `View History`)
  - Quick actions (`Upload Evidence`, `Add Task`, `View Timeline`)
  - Progress card (score, progress bar, compliance badge, evidence summary, last updated)
- Added action output event (`actionTriggered`) and kept handlers in container (`execution-screen.component.ts`).
- Right panel now updates based on selected OE context from store-derived VM values.

### 2) Accessibility and interaction quality
- Added ARIA roles/labels for:
  - Chapter list (`role="list"` + labeled interactive items)
  - Standards cards (`role="list"` / `aria-expanded` / `aria-controls`)
  - OE table region (`role="table"` / rows)
  - Action groups in the right panel (`role="group"` + labels)
- Added explicit keyboard-focus visibility (`:focus-visible`) on all interactive controls touched in plan scope.
- Added explicit OE `View` action button to avoid pointer-only row behavior.

### 3) Token governance and migration
- Confirmed no inline styles in touched feature templates.
- Confirmed no raw hex values and no raw `px` literals in touched execution feature styles.
- Added centralized semantic token aliases for not-applicable status:
  - `--color-execution-status-not-applicable-fg`
  - `--color-execution-status-not-applicable-bg`
- Synced SCSS token mirror entries in `design-tokens.scss`.
