# Phase 37.1 — Research: Journey Execution Screen (Mission Control Workspace)

## Objective context

Phase 37.1 is a task-execution workspace, not a dashboard. It must support rapid compliance operations with a 3-column structure:
- Left: chapter navigation and prioritization
- Center: standards and OE execution table
- Right: selected OE context, progress, and quick actions

## Requirements distilled

1. **Design system enforcement**
   - Follow `DESIGN_RULES.md` without deviation.
   - Use only tokenized values from `src/styles/tokens/*`.
   - No inline styles, no raw visual literals in feature styles/templates.
2. **Architecture constraints**
   - Build from scratch; do not reuse old execution layout/components.
   - Presentational components only in UI layer.
   - `@Input` / `@Output` + `ChangeDetectionStrategy.OnPush`.
3. **UX and workflow**
   - 3-panel mission-control layout with independent vertical scroll.
   - Sticky local headers for each panel.
   - Fast interactions: chapter switch -> standard list updates, standard expand/collapse, OE selection updates right panel.
4. **A11y and performance**
   - Keyboard navigation and focus states.
   - ARIA labeling for list/table/actions.
   - Lazy data loading by panel and `trackBy` usage.

## Recommended implementation shape

- **Container page** orchestrates state/event flow and maps store models to panel VMs.
- **Left panel components**
  - `chapter-navigation`
  - `chapter-item`
- **Center panel components**
  - `standards-panel`
  - `standard-card`
  - `oe-table`
  - `oe-row`
- **Right panel components**
  - `action-panel`
  - `progress-card`

## Data and state strategy

- Keep domain and network logic in store/service adapters.
- Use lightweight execution VMs for each panel and reusable card/table rows.
- Expand/collapse and selected OE state managed in container/store, not child components.

## Visual system strategy

- Add/extend semantic tokens only in token files when missing.
- Use subtle elevation and consistent card pattern across all three columns.
- Ensure risk/status variants map to semantic status tokens.
- Centralize any chart/progress color semantics into token aliases (no inline color arrays).

## Risks and mitigation

- **Risk:** accidental reuse of prior Journey structure
  - **Mitigation:** explicit replacement tasks and grep verification for legacy selectors/components.
- **Risk:** table/action panel becoming logic-heavy
  - **Mitigation:** strict presentational boundaries and event-only outputs.
- **Risk:** layout regressions on smaller widths
  - **Mitigation:** responsive breakpoint acceptance checks for each panel independently.
