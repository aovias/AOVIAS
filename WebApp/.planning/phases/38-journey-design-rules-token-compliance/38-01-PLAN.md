# Phase 38 — Journey module: full DESIGN_RULES token compliance

## Goal (backward from success)

- **100%** of Journey-related UI under `src/app/features/journey/` uses **only** CSS custom properties and foundation/theme tokens from `DESIGN_RULES.md` + `src/styles/tokens/*` — **no** raw hex/rgba for themeable colors, **no** arbitrary one-off px except where mapped to tokens (or documented edge case with comment per requirements).
- Visual and structural patterns **align with Control Center** as described in `DESIGN_RULES.md` (page shell, cards, spacing rhythm, shadows).
- Stepper, OE detail, list, execution, modals/drawers/panels share **one** vocabulary of tokens.

## must_haves

- [ ] Inventory of every Journey file with hardcoded colors/spacing documented and cleared.
- [ ] Colors use `var(--color-*)` and/or legacy aliases from `theme.tokens.css` per `DESIGN_RULES.md` — **no** new hex in feature styles.
- [ ] Spacing uses `var(--space-*)` (or approved `--spacing-*` aliases if Wave 0 adds them).
- [ ] Typography uses `var(--font-size-*)` / `var(--font-weight-*)` / `var(--line-height-*)` from foundation where applicable.
- [ ] Radius uses `var(--radius-*)`; single **“standard”** radius choice documented for Journey cards/buttons.
- [ ] Shadows use `var(--shadow-sm|md|lg)` from theme.
- [ ] Layout: page header + content padding + card sections consistent with `DESIGN_RULES.md` (e.g. page padding/gaps analogous to Compliance **24px / 16px / 24px** using `var(--space-6)`, `var(--space-4)`, etc.).
- [ ] Stepper states (active/completed/pending) token-only.
- [ ] Validation grep clean per checklist in this plan.

## Non-goals

- No API or store contract changes unless a template binding must change for class-only refactors.
- No redesign of information architecture — **style/token** alignment only.
