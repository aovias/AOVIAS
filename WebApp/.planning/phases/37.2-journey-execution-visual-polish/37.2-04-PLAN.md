# 37.2-04: Right column — mission-control cards and button hierarchy

## Objective

Split the right stack into **four clearly separated cards**: (1) Selected OE details, (2) Journey progress, (3) Primary actions, (4) Quick actions—with **consistent titles**, **internal spacing**, and **primary vs secondary vs tertiary** button weight—without changing click handlers or emitted events.

## Tasks

<task id="01" name="Section card frames">
- Ensure each logical section uses the same **card pattern** (padding, title style, border, radius, background) as established in 37.2-01.
- Add **vertical gap** between cards using `--space-*`.

**must_haves:**
- Four sections are visually distinct containers.
</task>

<task id="02" name="Typography and label/value rhythm">
- Normalize **section titles** (`h3`/heading tokens) vs body vs captions for tags, frequency, metadata.
- Improve **label vs value** distinction for OE code, description, and progress metrics.

**must_haves:**
- Right panel reads cleanly when scanning top-to-bottom.
</task>

<task id="03" name="Button hierarchy">
- **Primary:** Start/Resume (filled / strongest brand token usage already in design system).
- **Secondary:** View History (outline or muted fill per existing button patterns).
- **Quick actions:** tertiary visual weight (icon + label), equal heights, consistent grid.

**must_haves:**
- One obvious primary CTA per panel stack; quick actions do not compete with it.
</task>

<task id="04" name="Interaction polish">
- Hover/focus-visible on all buttons and quick actions; preserve `aria-label` where icons are solo affordances.

**must_haves:**
- Keyboard focus order remains logical; no regression in a11y attributes.
</task>

## Verification criteria

- [ ] Right column feels **secondary but strong**—structured, not cluttered.
- [ ] No API or `@Output` signature changes.

## must_haves (goal-backward)

- Right panel matches **reference card segmentation** and **action prioritization**.
