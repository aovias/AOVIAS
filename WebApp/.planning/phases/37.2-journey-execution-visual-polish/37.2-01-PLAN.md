# 37.2-01: Page shell — column weight, spacing rhythm, shared panel chrome

## Objective

Establish **enterprise workspace framing** for the execution screen: clearer **center-column emphasis**, consistent **page padding and gaps**, and **subtle elevation/border language** for the three columns—without changing TypeScript data flow or component APIs.

## Preconditions

- Read `execution-screen.component.ts` imports to confirm which child panels are rendered.

## Tasks

<task id="01" name="Grid and column hierarchy">
- Adjust `execution-screen__workspace` grid so the **center column reads as primary** (e.g. `minmax` ratios or fractional weights that give the center more horizontal space than left/right at desktop breakpoints).
- Harmonize `gap` and outer `padding` using existing `--space-*` tokens only; avoid introducing raw numbers.
- Ensure stacked/tablet breakpoints still read cleanly (no overlapping min-heights).

**must_haves:**
- At desktop width, center column is visually dominant vs side columns.
- Responsive rules remain token-only.
</task>

<task id="02" name="Shared panel chrome (depth without heavy shadow)">
- Apply consistent **surface + border + radius** treatment to the three panel wrappers (or a single BEM modifier shared via class on panel host), using `--color-bg-surface`, `--color-border-subtle`, `--radius-*`, and **light** `--shadow-*` where appropriate.
- If a repeatable “inset header” or “panel body” contrast is needed, add **semantic CSS variables** in `theme.tokens.css` + `design-tokens.scss` (e.g. optional `--color-bg-surface-raised` alias if not already present—reuse existing tokens first).

**must_haves:**
- Panels feel **segmented** vs flat page background (`--color-bg-page`).
- No new raw hex in component SCSS.
</task>

<task id="03" name="Top bar alignment">
- Tighten **back button + title block** alignment and vertical rhythm so the header row matches the structured feel of reference (spacing between kicker, title, and actions).

**must_haves:**
- Header row alignment is consistent and scannable; focus rings preserved.
</task>

## Verification criteria

- [ ] Visual check: center column occupies the visual “focus” band; side columns slightly recede.
- [ ] `npm run build` passes.
- [ ] No inline styles added; no raw `px`/`#` in touched SCSS except inside approved token files.

## must_haves (goal-backward)

- Execution page reads as a **layered enterprise workspace**, not a single flat strip.
- **No** changes to component `@Input`/`@Output` contracts or store usage in this plan.
