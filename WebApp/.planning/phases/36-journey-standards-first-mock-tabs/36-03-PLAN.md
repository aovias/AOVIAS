# 36-03: Standard-centric UX, Material tabs, and mock interactions

## Objective
Replace **accordion** standard UI with **nested clickable standards** in the left panel, **main panel** showing **Objective Elements for the selected Standard** plus **`JourneyTabsComponent`** (`mat-tab-group`): **Tasks**, **Evidence**, **Timeline**, **Findings**, **Analytics** — all **mock/local**, Material UI, badges for Core/risk, progress bars for compliance. Wire **`AccreditationDecisionPanelComponent`** to **`evaluateAccreditationEligibility`** from **36-02** (map `AuditLifecycleMode` → `NabhAssessmentPhase` or explicit assessment selector if lifecycle ≠ survey type). **Remove** broken API bindings from drawer/evidence flows.

## Tasks

<task id="01" name="ChapterNavigationPanel — nested standards">
### Left panel
- For **selected chapter** (or expandable sections per chapter), **list standards** as **clickable** rows (code + title + optional mini progress).
- **Click** calls `store.selectStandard(std.id)`; highlight active standard.
- Keep chapter list + search + risk sort from **36-01**; ensure keyboard focus/aria for nested list.

**must_haves:**
- No accordion that hides standard list; standards are **visible** under each chapter (expand/collapse per chapter is OK if all standards remain discoverable).
- **Clickable standard** loads **main** content for that standard.
</task>

<task id="02" name="JourneyMainWorkspace — standard-centric main">
### Main panel
- When **`selectedStandard`** is set: show **standard header** (code, title, description, metrics strip from **36-02**).
- List **OEs** for **`objectiveElementsForSelectedStandard`** (cards/table — reuse existing OE card patterns).
- **Remove** reliance on accordion for standards; **OE list** is scoped to **one standard** at a time.

**must_haves:**
- Empty state when no standard selected.
- OE click opens drawer / keeps existing behavior with **local** patch only.
</task>

<task id="03" name="JourneyTabsComponent">
### New component `journey-tabs` (folder with children)
- Use **`MatTabsModule`** — **`mat-tab-group`** with five tabs:
  1. **Tasks** — list action plans from OEs in selected standard (aggregate `actionPlans[]`); Add/Edit task **UI-only** (dialog or inline form) mutates **local** `OeActionPlan[]` in store snapshot.
  2. **Evidence** — mock upload (file picker adds to **local** `OeEvidenceItem[]` for selected OE); list files per OE; **no** HTTP upload.
  3. **Timeline** — activity from `OeHistoryEvent[]` + synthetic events for “score change” / “evidence added” from local actions.
  4. **Findings** — non-compliance, observations, risks (derive from low scores, open issues, or mock fields).
  5. **Analytics** — compliance %, core failures, OE score distribution, **charts/bars** using derived scoring + **36-02** utils.

**must_haves:**
- Badges: **Core** / **Risk** on OE rows where applicable.
- **Progress bars** for compliance (Material `mat-progress-bar` or existing CSS).
- Tabs **independent** — switching tabs does not clear selection.
</task>

<task id="04" name="journey.component — compose layout">
### Page shell
- Wire **left**: `ChapterNavigationPanel`; **center**: `JourneyMainWorkspace` + `JourneyTabsComponent` (below OE list or side-by-side per design — **prefer** tabs **below** main OE list for clarity).
- Remove obsolete **workspace-tabs** (`standards` vs `evidence`) if replaced by **36-03**; consolidate **evidence** tab.
- Hidden file input for evidence: keep **local** or move under Evidence tab.

**must_haves:**
- Light/dark theme consistent with existing journey CSS variables.
- **No** `journeyApiErrorMessage` from network for core path — **or** only for unrelated future calls.
</task>

<task id="05" name="OeDetailDrawer — local-only">
### Drawer
- Remove **PATCH** calls; edits apply via **`patchObjectiveElement`** on store only.
- Evidence upload triggers **local** `replaceObjectiveElementEvidence`.

**must_haves:**
- No `submitObjectiveElementPatch` HTTP.
</task>
