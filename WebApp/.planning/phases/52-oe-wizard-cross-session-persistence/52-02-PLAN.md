# Phase 52 — Wave 2: Server draft API + cross-device load/merge

## Goal

**Persist wizard draft to the backend** (database via Gateway) so login from **another device** loads the same progress. Add **GET/PATCH** (or POST) client methods, `**revision` / `updatedAt`** handling, and **merge policy**: **server wins** if newer than session `savedAt`; otherwise optional prompt or last-write-wins per product.

**Prerequisite:** Backend route agreed with API owner (see `52-RESEARCH.md` §5). If API is not ready, implement **service stubs + feature flag** and keep session-only behavior.

## must_haves

- DTOs: `OeWizardDraftDto` (payload + `revision` + `updatedAt` ISO).
- `JourneyDataService` (or dedicated small service): `getOeWizardDraft(journeyId, oeId)`, `putOeWizardDraft(..., body, revision?)` with **409** handling → refresh + retry once.
- On journey/OE selection and after auth: **fetch draft** → apply to store → then **merge session** per 52-RESEARCH §4.
- **Debounced PATCH** (e.g. 1–2s after `markWizardDirty`) to avoid spam; **flush on wizard close** (`closeOeWizardWithoutConfirm`).
- Logout / `dismissOeWizardDirty`: define whether server draft is deleted or kept (default: **keep** draft for resume).
