# Phase 56 — Plan 02: Store scope, subscription discipline & stale-response guards

## Phase goal (backward)

After this wave, **one `JourneyWorkspaceStore` instance** serves both the Journey dashboard and execution routes (where the product expects shared workspace state), eliminating **spurious abort** when navigating `/app/journey` ↔ `/app/journey/execution` while reads are in flight. **Workspace init** and **chapter standards** loads use **latest-wins** semantics (`switchMap` or manual generation counters) so **superseded** HTTP may abort **only** when a **newer** load replaces it — not when the user is idle on the same screen. **Navigation away** from the whole Journey feature still destroys the shell and cancels in-flight work (correct behavior).

## must_haves

- [ ] New lightweight **route shell** component (name e.g. `JourneyFeatureShellComponent`) hosts `providers: [JourneyWorkspaceStore]` + `router-outlet`; **remove** `JourneyWorkspaceStore` from `JourneyComponent` and `JourneyExecutionShellComponent` providers arrays.
- [ ] `routes.ts` nests existing child routes under the shell; **lazy imports** updated; **no duplicate** store providers on children.
- [ ] `initFromRoute` / `loadWorkspaceFromApi` / `reloadAfterOperationalModeChange` refactored to **serialize** overlapping workspace loads (e.g. `Subject` + `switchMap`, or incrementing `workspaceLoadGen` and ignoring stale `next` handlers).
- [ ] `ensureChapterStandardsLoaded` refactored to **latest chapter wins**: abort or ignore superseded responses; never merge standards for a chapter that is **no longer selected** when product intent is “current chapter only” (document choice in code comment).
- [ ] `takeUntilDestroyed` remains for **component-level** subscriptions only where appropriate; long HTTP chains tied to store should use **store-owned** teardown (`DestroyRef` on store is still valid for **full feature exit**).
- [ ] `ng build` passes; smoke: open execution from dashboard without double full reload regression (single store `initFromRoute` may run once per shell entry — acceptable; avoid **duplicate** `initFromRoute` from **both** child `ngOnInit` if shell already calls it).
