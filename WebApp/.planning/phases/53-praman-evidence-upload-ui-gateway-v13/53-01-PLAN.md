# Phase 53 — Wave 1: Evidence upload contracts, validation, payload builders, service stubs

## Goal

Align the codebase with **Gateway API v1.3** evidence endpoints: add **shared constants**, **pure `FormData` builders** (no HTTP), **frontend validation** helpers, and **`JourneyDataService` methods** `uploadSingleEvidence` / `uploadBulkEvidence` that perform **`HttpClient.post`** to the correct URLs — **without** any component, store, or wizard code calling them yet.

## must_haves

- [ ] Document **v1.3** routes: single `POST …/evidence`, bulk `POST …/evidence/bulk` in `docs/backend/journey-screen-api-spec.md` (delta section or §3.2 extension) with field names matching the product brief.
- [ ] Constants: **`EVIDENCE_MAX_FILE_SIZE_BYTES`** (= 10 MB), **`EVIDENCE_BULK_MAX_FILES`** (= 15), exported from a small util file (e.g. `oe-evidence-upload.constants.ts`).
- [ ] `validateEvidenceFilesForMode(files: File[], mode: 'single' | 'bulk'): { ok: true } | { ok: false; message: string }` — enforce count (single → 1 file max for that mode if you treat “single” strictly as one file in state) and per-file size; **bulk** rejects &gt; 15 files.
- [ ] `buildSingleEvidenceFormData(params)` → `FormData` with keys **`file`**, **`evidenceType`**, optional **`title`**, optional **`metadata`** (stringify JSON if value is object).
- [ ] `buildBulkEvidenceFormData(params)` → `FormData` with **`files`** (append each `File`; use **`files` as repeated field name** or `files[]` **only** if Gateway spec/OpenAPI confirms — default to repeated `files` parts mirroring common ASP.NET/Gateway patterns; **comment** in code to verify against Gateway).
- [ ] `JourneyDataService`: **`uploadSingleEvidence(journeyId, objectiveElementId, formData: FormData)`** → POST to `…/evidence`; **`uploadBulkEvidence(journeyId, objectiveElementId, formData: FormData)`** → POST to `…/evidence/bulk`. Reuse `environment.apiBaseUrl` + same **`journeyBase` / version** pattern as existing `postEvidenceMultipart`. **Refactor** existing `postEvidenceMultipart` to delegate to `buildSingleEvidenceFormData` + `uploadSingleEvidence` **or** keep old method as thin wrapper with deprecation comment — **no** breaking changes to other callers.
- [ ] **No new invocations** from UI: grep gate — wizard and store do not reference `uploadSingleEvidence` / `uploadBulkEvidence` after this wave (only unit tests or private dev-only harness allowed in Wave 2 with `ngDevMode` guard).
- [ ] **`triggerUpload()`** in Wave 2 will call validation + builders + optional `console.debug` of `FormData` keys; this wave defines builders only.
