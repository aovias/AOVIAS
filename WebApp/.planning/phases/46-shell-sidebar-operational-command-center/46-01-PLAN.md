# Plan 01 — Information architecture, section model, and nav item UX

## Goal (phase)

Define and implement the **top-to-bottom shell sidebar structure** as an **operational command center**: **named sections**, **logical grouping** of all **existing** app modules (no removals), **clear hierarchy** with **Journey** as the emphasized primary entry under **Compliance Execution**, and **consistent nav row anatomy** (icon, label, optional badge placeholder, states).

## must_haves

- [ ] Sidebar follows **fixed section order**: Brand & system header → **Context panel** → **Primary navigation** (grouped) → optional **Quick actions** region (stub or placeholder per Plan 03 if deferred).
- [ ] **Section headers** are visually distinct (uppercase or subtle label), with **breathing room** between sections; no single undifferentiated list.
- [ ] **Compliance Execution** group contains **Journey** (strongest emphasis), **Standards / Chapters** (or equivalent), **Evidence**, **Tasks** — labels match product language; routes **map to existing** lazy routes without deleting modules.
- [ ] **Dashboard** group contains **Overview** and **Analytics / Insights** (or current dashboard children) as **first-class** rows.
- [ ] **Action Center** group exists as a **dedicated** block: Findings / Non-Conformances, Issues / Risks, Alerts / Notifications — as **navigation targets** (even if some routes are stubs behind feature flags).
- [ ] **Audit Management**, **Knowledge & Documentation**, **Administration** groups populated per **stakeholder list**; items **disabled** with explanation when mode/role disallows (prefer disabled + tooltip over silent hide where possible).
- [ ] Every row supports **states**: default, hover, active (strong — background and/or **start border** + icon/text), disabled.
- [ ] **Scalability**: document **pattern** for adding rows (new subsection or new group) without redesign — e.g. config-driven sections with stable sort keys.
