# Plan 02 — Context panel, operational mode, Action Center integration

## Goal (phase)

Elevate the **context panel** to a **card-like, elevated** “where am I” surface: **organization / hospital**, **active framework**, **operational mode** (Self Assessment, Internal Audit, Final Audit), optional **compliance progress**, and **clickable** affordance opening the **existing** hospital/framework switcher (extended if needed for mode). Integrate **Action Center** rows with **badge placeholders** (neutral / warning / critical) ready for live counts.

## must_haves

- [ ] Context panel is **visually distinct** from nav list (elevation, surface token, radius) per **minimal** enterprise aesthetic (no heavy chrome).
- [ ] **Mode** is visible as text + optional icon; changing mode uses **clear** flow (dialog step, segmented control in switcher, or dedicated picker — **one** pattern chosen and documented).
- [ ] **Compliance progress** region: either implemented with real data **or** structured **empty/placeholder** with accessible label (“Progress unavailable”) — no broken progress UI.
- [ ] **Click** on context panel (or explicit control) opens **switcher**; loading/spinner behavior preserved for async context switch.
- [ ] **Action Center** items show **badge slots** (can display “0” or hide when zero per product rule — document rule).
- [ ] **Badge semantics**: neutral count, warning (pending), critical (high risk) — **color tokens** only; consistent **placement** (end of row).
- [ ] **Context-aware stubs**: rules documented for **disabling** Audit Management when mode incompatible (labels explain why in tooltip or `aria-description`).
