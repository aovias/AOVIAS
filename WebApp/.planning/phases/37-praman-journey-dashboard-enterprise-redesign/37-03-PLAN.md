# 37-03: Insights charts, semantic chart tokens, a11y, and readiness verification

## Objective
Deliver the final enterprise dashboard layer for insights/charts and complete strict token migration by centralizing chart palette tokens, adding accessible interactions, and verifying mobile/desktop readiness with zero hardcoded visual drift.

## Tasks

<task id="01" name="Insights and charts section implementation">
### Build three chart cards and interaction hooks
- Render 3 equal cards:
  - OE Score Trend (line chart)
  - Chapter Improvement (bar chart)
  - Risk Evolution (area chart)
- Include title + "Last 7 days" filter affordance in each card.
- Emit chart click events for future drill-down integration.
- Keep chart dataset mapping in container/store adapter code.

**must_haves:**
- Hover tooltip works for each chart.
- Chart cards degrade gracefully for empty datasets.
</task>

<task id="02" name="Centralize semantic chart tokens">
### Eliminate hardcoded chart colors
- Add centralized chart semantic tokens in token layer, for example:
  - `--color-chart-line-primary`
  - `--color-chart-line-secondary`
  - `--color-chart-area-fill`
  - `--color-chart-bar-positive`
  - `--color-chart-grid`
  - `--color-chart-tooltip-bg`
- Mirror tokens into `design-tokens.scss` when required by SCSS usage.
- Replace any raw chart color arrays with token-driven palette resolver utility.

**must_haves:**
- No chart component uses literal hex colors.
- Light/dark palette differences are defined only in token files.
</task>

<task id="03" name="Accessibility and keyboard compliance sweep">
### Ensure enterprise accessibility baseline
- Keyboard navigation:
  - journey mode cards selectable by keyboard
  - action bar buttons focus-visible and ordered
  - chart cards reachable and actionable
- Add ARIA labels/roles for card groups, badges, and chart regions.
- Validate contrast using semantic tokens; adjust token choices if needed.

**must_haves:**
- Locked journey modes announce locked state and tooltip reason.
- Focus states are visible in both themes.
</task>

<task id="04" name="Quality gates and migration verification">
### Execute strict checks before phase completion
- Verify no inline styles in Journey dashboard templates.
- Verify no raw hex/px in touched Journey feature styles (except token definitions).
- Verify all required sections exist and are responsive.
- Verify old Journey dashboard UI structure is not rendered.
- Produce/update verification notes for build/test evidence.

**must_haves:**
- `ng build` passes.
- Lint passes for touched files or documented residual pre-existing issues only.
</task>

## Verification criteria
- [ ] Three insight charts are present with filter affordance and hover tooltip.
- [ ] Chart colors come exclusively from centralized semantic tokens.
- [ ] Keyboard/ARIA behavior satisfies dashboard interactions.
- [ ] No inline CSS or hardcoded visual constants in touched dashboard feature files.
- [ ] Build succeeds and responsiveness is verified at mobile/tablet/desktop widths.

## must_haves (goal-backward)
- Dashboard feels premium and actionable while remaining maintainable.
- Token governance is centralized and future-proof for branding.
- Journey dashboard is execution-ready for enterprise UAT.
