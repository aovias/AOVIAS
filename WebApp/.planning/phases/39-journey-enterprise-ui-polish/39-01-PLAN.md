# Phase 39 — Wave 1: Design system documentation + token foundation

## Goal (backward from success)

**`DESIGN_RULES.md`** documents the full **enterprise polish system** for Journey (and aligned modules): hairline borders, elevation usage, card density modes, badge and icon sizing, spacing enforcement between sections, and button hierarchy — with every new name resolving through **`src/styles/tokens/*`**. **`foundation.tokens.css`** (and **`theme.tokens.css` only if new shadow/border *semantic* tiers are required) contains the aliases; **no** hex in feature code introduced by this wave.

## must_haves

- [ ] New or clarified **aliases** in `foundation.tokens.css`: e.g. `--border-width-hairline` (1px), optional `--border-width-default` mapping to existing usage, `--card-padding-compact` and `--card-padding` (or rename current `--card-padding` to “normal” and add compact), `--icon-size-sm`, `--icon-size-md`, `--section-gap-y` (or reuse `--spacing-lg` with explicit Journey rule).
- [ ] **`DESIGN_RULES.md`** new/expanded sections (minimum):
  - **Border system:** standard hairline width; when to use border vs `box-shadow` / background step; link to `--color-border-subtle` / `--border-color`.
  - **Elevation:** which `--shadow-*` (and optional `--shadow-xs` / `--shadow-card` if added in theme) for cards vs sticky panels vs drawers; “soft, layered” guidance.
  - **Color discipline:** primary brand for primary actions and critical links only; neutral surfaces dominate; reduce decorative blue.
  - **Card density:** **compact** (chapter rail, dense lists) vs **normal** (hero metrics); padding tokens each.
  - **Badges:** radius, padding, font-size token references; semantic colors (success / warning / neutral) via existing CSS variables.
  - **Icons:** sm/md sizes and when to use; alignment with text cap height.
  - **Spacing:** enforce section gaps using `--space-*` scale; rule of thumb for “related vs separated” groups.
  - **Buttons:** primary / secondary / tertiary visual rules (height via `--button-height`, weight, border vs ghost).
- [ ] **Journey implementation mapping** table in `DESIGN_RULES.md` updated with new rows (mirror Phase 38 table style).
- [ ] Build passes; no breaking changes to non-Journey imports (tokens additive).

## Non-goals

- No edits under `src/app/features/journey/` in this wave (documentation + global tokens only).
- No new product features or routes.
