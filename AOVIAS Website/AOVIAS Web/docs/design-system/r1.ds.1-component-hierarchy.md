# R1.DS.1 — Component Hierarchy

**Date:** 2026-07-21  
**Purpose:** Composition trees from shell → section → leaf

---

## Global composition (public marketing pages)

```
AppShell
├── SkipToContent
├── SiteHeader
│   ├── HeaderChrome
│   ├── SiteLogo
│   ├── MainNav → MegaMenuTrigger / MegaMenuPanel
│   ├── UtilityNav / SearchEntry
│   └── MobileNav → MobileDrawer
├── MainContent
│   └── [Layout variant]
│       └── Page sections…
└── SiteFooter
```

---

## Layout variants

### MarketingLayout

```
MarketingLayout
└── PageContainer
    └── children (Hero → SectionSurface bands → CtaSection)
```

### ProductLayout

```
ProductLayout
└── PageContainer
    ├── ProductHero | page Hero
    ├── ProductNavigation (optional)
    └── product sections (FeatureShowcase, CapabilityGrid, Spec, CTA)
```

### TechnologyLayout

```
TechnologyLayout
└── PageContainer
    ├── Hero (+ brand diagram / atmosphere)
    ├── PlatformSectionBand* / FeatureGrid / PrincipleCard grids
    └── CtaSection
```

### KnowledgeLayout / DocumentationLayout

```
KnowledgeLayout
├── KnowledgeCover | list header
├── ResourceGrid | Article detail
│   ├── ReadingProgress
│   ├── TableOfContents (docs)
│   └── AuthorBlock / CategoryBadge
└── Pagination / SearchResults
```

### AuthenticationLayout

```
AuthenticationLayout
├── BrandAtmosphere / brand panel
└── Auth form (SignInForm → Form Engine → Input/Button/Alert)
```

### LegalLayout

```
LegalLayout
├── PageHeader
└── prose ContentWrapper (minimal chrome)
```

### ErrorLayout

```
ErrorLayout
└── ErrorState | MaintenanceScreen | ComingSoon
```

## Section composition patterns

### Hero band

```
SectionSurface (tone: hero|elevated)
└── Hero | ProductHero
    ├── eyebrow / Heading / Text
    ├── CTA group (Button | MarketingCtaLink)
    └── Media
        ├── BrandAtmosphere | DomainScene | KnowledgeCover
        ├── MediaSlotView | ProductFrame
        └── Product console / diagram
```

### Content band

```
SectionSurface
├── SectionHeader
├── Grid | FeatureGrid | ResourceGrid | PricingGrid
│   └── Card role (Feature|Value|Principle|Article|Pricing|…)
└── MarketingReveal / MotionReveal (optional wrap)
```

### Trust / proof band

```
SectionSurface
├── SectionHeader
├── LogoCloud | CustomerLogoGrid | SuccessMetrics
├── TrustBadge row | SecuritySection | ComplianceGrid
└── Testimonial | QuoteBlock | Faq
```

### CTA band

```
CtaSection
├── Heading + supporting Text
└── Button / MarketingCtaLink / EnterpriseCta
```

## Card composition (shared)

```
Card shell (or domain card root)
├── IconWrapper | media thumb (optional)
├── CardTitle / Heading
├── CardDescription / Text
├── Badge / CategoryBadge (optional)
└── CardFooter → Link | Button
```

Domain cards (FeatureCard, PricingCard, ArticleCard) may embed this structure without exporting Card parts.

## Hierarchy rules for R1.DS.2+

1. Tokenize **leaves and shells** first (Button, Surface, Text, SectionSurface).
2. Domain cards inherit surface/type/space roles from shells — do not invent per-card color systems.
3. Atmosphere and diagrams consume `color.brand-atmosphere`, `elevation.*`, `motion.*` only through their roots.
