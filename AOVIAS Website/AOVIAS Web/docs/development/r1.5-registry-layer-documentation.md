# R1.5 — Registry Layer Documentation

**Date:** 2026-07-20

---

## Purpose

Centralize SDK registration, service resolution, and mode selection so pages never instantiate clients.

## Core type

`SdkClientRegistry` in `@aovias/sdk/core`:

- `register(key, { id, mode, label, create })`
- `resolve<T>(key)` — lazy singleton per key
- `mode(key)` — diagnostics

## Website composition root

`apps/website/src/registries/sdk-registry.ts`

Bootstraps mock adapters for:

`identity` · `commerce` · `contact` · `knowledge` · `search` · `checkout`

Public getters: `getIdentityClient()`, `getCommerceClient()`, …

## Rules

1. No page `new`s an SDK client  
2. Form adapters call registry getters  
3. R2 swaps `create` factories when `featureFlags.*Live` and base URLs are set
