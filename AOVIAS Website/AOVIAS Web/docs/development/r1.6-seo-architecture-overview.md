# R1.6 — SEO Architecture Overview

**Date:** 2026-07-20  
**Status:** Complete  
**Deployment:** Not started

---

## Purpose

Centralize discoverability so every public route inherits defaults and overrides metadata through builders — not hardcoded page-local SEO.

## Layers

| Layer | Path | Role |
| --- | --- | --- |
| Config | `apps/website/src/config/seo.ts` | Org, robots, sitemap registry, OG map, verification env keys |
| Builders | `apps/website/src/lib/seo/*` | Canonical, metadata, Open Graph, Twitter, robots, sitemap, JSON-LD |
| Public API | `apps/website/src/seo/` | Preferred import surface + entity graph + schema registry |
| Routes | `apps/website/src/app/**/page.tsx` | `createPageMetadata` + `buildPageSchemas` + feature schemas |
| Assets | `apps/website/public/og/*` | Section preview images |

## Builder map

- **Metadata:** `createPageMetadata` / `createRootMetadata`
- **Canonical:** `buildCanonicalUrl` / `getSiteUrl`
- **Open Graph:** `buildOpenGraph`
- **Twitter:** `buildTwitterCard`
- **JSON-LD:** `buildPageSchemas`, `buildFaqPageSchema`, `buildDefaultSiteSchemas`
- **Robots:** `buildRobotsConfig`
- **Sitemap:** `buildSitemapEntries` + dynamic collectors in `app/sitemap.ts`

## Entity & Knowledge Graph

Reusable entity model in `src/seo/entities/`:

- AOVIAS (Organization)
- AOVIAS Platform
- AOVIAS Command
- AOVIAS Studio
- Technology
- AI
- Industries
- Platform Services

Entities define canonical names, paths, OG images, and relations for consistent structured data and AI understanding.

## Design rules

1. Root layout emits Organization + WebSite once (`@id` nodes).
2. Pages link via `publisher: { '@id' }` — no full Organization duplication.
3. FAQ / Product / Job schemas only from real on-page content.
4. Non-production: noindex + empty sitemap + robots disallow all.
