# EBAS — Visual Before vs After Assessment

## Before

- Nearly every hero used the same procedural square blueprint grid.
- Mid-page `SectionSurface tone="blueprint"` repeated the same grid wash.
- CTA / auth shells defaulted to the blueprint façade.
- AI, Security, Products, and Company felt atmospherically identical.
- Live production build previously lacked `data-atmosphere` (stale build), so registry work was invisible until rebuild.

## After

Verified live (`data-atmosphere` attributes on production server):

| Page | Observed atmosphere |
|------|---------------------|
| `/` | `enterprise-abstract` (+ mid-page `architecture`) |
| `/technology/ai` | `ai-neural-network` (node/link field, not square grid) |
| `/products` | `workflow` (lane bands) |
| `/technology/trust` | `security-geometry` (triangular mesh + diamond marks) |

Additional wired families (source + rebuild):

- Resources → `knowledge-pattern`
- Pricing → `subtle-texture`
- Contact → `aurora`
- Company → `corporate-gradient`
- Legal → `minimal-neutral`
- Auth → `trust-geometry`
- Engineering → `blueprint-grid` (intentionally reserved)
- Platform → `platform-grid`

## Customer perception change

| Dimension | Before | After |
|-----------|--------|-------|
| Page uniqueness | Low — same grid everywhere | High — subject-matched silhouette |
| Blueprint monotony | Dominant | Limited to engineering contexts |
| AI identity | Generic tech grid | Neural node/link field |
| Security identity | Generic tech grid | Geometry + diamond bounds |
| Product identity | Generic tech grid | Workflow lanes |
| Legal readability | Same hero energy | Quiet minimal column |

## Constraints preserved

Layouts, routing, content, component architecture, and semantic token system unchanged.
