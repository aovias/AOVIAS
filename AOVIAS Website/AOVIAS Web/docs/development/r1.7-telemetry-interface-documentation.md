**Date:** 2026-07-20  
**Status:** Complete

## OpenTelemetry-aligned model

| Concept | Type | Role |
| --- | --- | --- |
| Attributes | `Attributes` | Dotted key/value bag |
| Context | `TelemetryContext` | traceId, spanId, session, campaign, baggage |
| Event | `TelemetryEvent` | Named, versioned, attributed record |
| Span | `Span` | Timed operation within a trace |
| Trace | `Trace` | Logical unit of work handle |

These are **conceptual** alignments — the OpenTelemetry JS SDK is not a runtime dependency in R1.7.

## Core interfaces

### `AnalyticsProvider`

Pluggable sink. Must declare `transmits`. Pages never import implementations.

### `TelemetryClient`

Application facade: track*, consent, campaign, span/trace helpers.

### Supporting types

- `PageView`, `ConversionEvent`, `ErrorEvent`, `NavigationEvent`
- `SessionInformation`, `CampaignInformation`
- `ConsentState` / `ConsentCategory`
- `EventDefinition` / `EventName`

## Compatibility rule

Future providers and product apps (Command / Studio) should emit the same `TelemetryEvent` shape so exporters can normalize to OTLP later without renaming website events.
